# Яндекс Станция как устройство голосового ввода

Ресёрч 2026-09-06. Идея Sergey: у него есть портативная Станция Стрит,
использовать её как микрофон для ввода в проекты через навык Алисы.

**Вывод: технически работает и встаёт на нашу архитектуру почти без швов, но
годится только для коротких команд.** Длинный монолог продиктовать нельзя —
управления микрофоном в API нет, пауза на размышление обрывает реплику. То
есть это второй канал к VK, а не замена ему.

## Как устроен навык

Навык — это веб-сервис на своём HTTPS-адресе. Яндекс распознаёт речь сам и
шлёт на webhook POST с уже готовым текстом:

```json
{
  "request": { "command": "запиши мысль про кэширование",
               "original_utterance": "запиши мысль про кэширование" },
  "session": { "new": false, "user_id": "...", "session_id": "..." },
  "meta":    { "client_id": "...", "locale": "ru-RU" }
}
```

Ответ — JSON с текстом, который Алиса озвучит.

То есть **STT достаётся бесплатно и в качестве Яндекса**, без нашего whisper,
без BlackHole, без микрофона в кармане.

## Почему у нас это сработает, а у большинства нет

Главная боль всех, кто прикручивал к Алисе ChatGPT — **таймаут 4.5 секунды**.
В них входит сеть, работа сервиса и доставка ответа. Не уложился — Алиса
говорит «навык не отвечает» и закрывает сессию. Отсюда все костыли из статей:
«скажите готово», фоновая музыка, капчи, пагинация ответов.

**Нам этот таймаут почти не мешает, потому что ответ мы отдаём не через
Алису.** У нас уже есть каналы: текст в VK, голос на маке через плеер. Навык
может ответить «принял» за 200 миллисекунд, а сам инжектит текст в сессию —
дальше работает обычный маршрут.

То есть Алиса нужна ровно как **устройство ввода**, чем Sergey и спросил.

## Что требуется, и что у нас уже есть

| требование платформы | статус |
|---|---|
| HTTPS-адрес, не IP | есть — `cashflow-game.ru` на Caddy |
| подтверждение прав на домен | домен наш |
| публичный доступ к webhook | Caddy уже проксирует `/v1/voice/*` |
| аккаунт Яндекса | есть, там же SpeechKit для синтеза |
| приватный навык | доступен только автору, модерация проверяет лишь иконку и активационное имя |

Отдельный сервис поднимать не нужно — это ещё один маршрут в существующем
`voice-backend`.

## Главное ограничение: только короткие команды

**Длинный монолог продиктовать нельзя.** Проверено 2026-09-06: навык получает
уже завершённую и распознанную реплику, управления микрофоном в API нет.
Разработчик не может продлить прослушивание, отключить определение пауз,
включить режим диктовки или удержать микрофон открытым. Пауза на размышление
завершает реплику, и навык получит обрывок.

Официальных цифр (сколько секунд слушает, какая пауза обрывает) Яндекс не
публикует — их можно установить только экспериментом на конкретном
устройстве. Но само отсутствие управления микрофоном подтверждается
документацией и опытом разработчиков.

**Что это меняет.** Сценарий «надиктовать пять минут размышлений» остаётся за
VK: там кнопка записи удерживается сколько нужно, паузы не мешают. Станция
закрывает другое — короткие команды без рук:

- «запиши мысль про кэширование в очереди»
- «какой статус у голосового проекта»
- «переключись на воис»
- «что там с расшифровкой докладов»

Это не замена основному каналу, а второй, для реплик в одно предложение.

Обходной путь — диктовать частями, навык подтверждает каждый кусок и просит
продолжать. Но это неудобно ровно там, где нужна связная мысль, и гарантии,
что длинная пауза попадёт в одну реплику, всё равно нет.

## Ограничения, которые никуда не денутся

**Активационная фраза.** Каждый заход: «Алиса, запусти <имя навыка>». Внутри
сессии дальше можно говорить подряд, сессия живёт несколько минут без реплик
и закрывается по «Алиса, хватит».

**Навык не может заговорить первым.** Инициировать разговор нельзя — только
отвечать на реплику. Значит уведомление «задача готова» через колонку не
толкнуть, нужен запрос от человека. Наши push-каналы (VK, мак) этим не
ограничены.

**Аудио уходит в Яндекс.** Принцип «on-device first» в проекте — про скорость
и экономию, а не догма (уточнение Sergey, 2026-09-06): облако допустимо, если
не в ущерб качеству распознавания. Здесь качество как раз яндексовское, так
что противоречия нет.

**Нужен интернет.** Без сети Станция Стрит остаётся Bluetooth-колонкой и
понимает лишь команды управления музыкой. Навык не работает.

**Длина ответа** — до 1024 символов по одним источникам, до 5000 по
документации. Для «принял» неважно.

## Чем это не заменяет носимый девайс

| | Станция | MCU-клиент |
|---|---|---|
| стоимость | 0, колонка есть | ~20к плюс месяцы работы |
| готовность | вечер работы | не начато |
| кнопка | нет, только голосовая активация | физическая PTT, ради неё всё и затевалось |
| носимость | колонка стоит рядом | на поясе, гарнитура на голове |
| в дороге и на бегу | нет | да |
| приватность | запись у Яндекса | своё железо |

Станция закрывает сценарий «дома или в комнате, руки заняты, говорю в
пространство». Носимый девайс — «в движении, в шуме, с кнопкой». Это разные
сценарии, и первый достаётся почти даром.

## Как поднято (2026-09-07)

Маршрут `POST /v1/alice/<секрет>` в `voice-backend`. Включается переменной
`ALICE_PATH_SECRET` в `/etc/voice-backend.env`; без неё маршрут не
существует. `ALICE_SKILL_ID` — необязательная сверка навыка.

**Защита.** Bearer-токеном не закрыть: платформа заголовков не шлёт. Поэтому
секрет живёт в пути (32 hex-символа), а поверх сверяется `skill_id` из тела.
Послабление в авторизации действует только на префикс `/v1/alice` и только
когда навык настроен — проверяется тестом.

**Почему отвечаем сразу.** Ответ «Передал» уходит за миллисекунды, инжект
идёт фоновой задачей. Иначе не уложиться в 4.5 секунды. Обратная сторона:
если инжект не дошёл, сказать об этом уже некому — остаётся запись в журнале.

**Маршрутизация.** Реплика идёт туда же, куда голосовые из VK — по
`focus.json`. Резолвер фокуса вынесен из VK-блока и стал общим: две копии
одной логики разъехались бы на первой правке.

**Caddy** проксирует `/v1/alice/*` на бэкенд отдельным блоком.

Проверено сквозным прогоном: HTTPS → Caddy → бэкенд → инжект в сессию под
фокусом, `focus_source=focus` в журнале.

## Что осталось сделать руками

1. Консоль Диалогов, «Создать диалог» → «Навык в Алисе»
2. Backend: `https://cashflow-game.ru/v1/alice/<секрет из env>`
3. Тип доступа — **Приватный**
4. Заполнить обязательное: активационное имя, примеры запросов, имя
   разработчика, категорию, описание, иконку 224×224
5. Опубликовать (приватная модерация проверяет только имя и иконку)
6. Прописать `ALICE_SKILL_ID` в env и перезапустить сервис

Активационное имя выбирать осторожно: Алиса не должна путать его с другими
навыками и обычными фразами.

## Оценка работ

Один вечер: маршрут в `voice-backend`, разбор запроса Диалогов, инжект текста
в сессию по фокусу, ответ-заглушка. Плюс регистрация навыка в консоли и
приватная публикация.

Но браться стоит, только если короткие команды нужны сами по себе. Если
ожидание было «говорить в колонку вместо VK» — оно не оправдается, и вечер
уйдёт впустую.

Незакрытый вопрос — что отвечать голосом сразу. Варианты: подтверждение
приёма («записал»), либо короткая выжимка, если успеваем за 4.5 секунды.
Решать на живом опыте, а не заранее.
