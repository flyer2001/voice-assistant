# Разбор чужого промпта «Разборщик встреч» и сравнение с нашим подходом

Источник: практикум Федоренко 06.10.2026, файл роздан участникам.
Лежит в `bench/practicum-ai-2026-10-06/prompt_deepseek_razbor_vstrech_v_zadachi.md`
— 733 строки, 58 КБ, 9 разделов и 2 приложения.

Задача промпта ровно наша: из транскрибации встречи получить задачи,
исполнителей, сроки, решения и риски.

## Из чего он состоит

| Раздел | Что внутри |
|---|---|
| 1. Роль и миссия | Идентичность, метафора «секретарь-протоколист с маркером», 6 принципов таблицей, портрет пользователя |
| 2. Компетенции | Области экспертизы с уровнями, что умеет, **чего не делает** |
| 3. База знаний | Что считается задачей, определение ролей, работа со сроками, матрица приоритетов, особенности транскрибаций, справочник команды, глоссарий |
| 4. Алгоритм | Decision tree по типу входа, протокол уточнений, **повторный проход**, проверка перед выдачей |
| 5. Форматы выхода | Матрица «тип запроса → формат», 7 шаблонов (полный разбор, компактный, мессенджер, по людям, таблица, Гант), правила форматирования |
| 6. Примеры | 8 примеров, включая краевые: текст без задач, запрос не по теме, размытые «мы договорились» |
| 7. Правила | 9 железных правил, сохранение роли, эскалация, дисклеймер |
| 8. Стиль | Тон, оформление, длина |
| 9. Чек-лист качества | 6 блоков проверок перед выдачей |

## Что в нём сделано хорошо

**Прослеживаемость.** Каждая задача обязана иметь цитату из текста до 15 слов:
«не можешь найти цитату — задачи нет». Это не пожелание «не выдумывай», а
механизм: читатель сводки проверяет любой пункт за десять секунд, не
перечитывая исходник.

**Пробел виден, а не заполнен.** Нет срока — `⚠️ не назван`, нет исполнителя —
`⚠️ не назначен`, выведенное самим ассистентом помечается `(вывод)`,
`(вероятно)`, `(дату уточнить)`. Отсутствие данных становится видимым объектом,
а не исчезает.

**Повторный проход (4.3).** После первого извлечения — второй прогон по списку
речевых маркеров: обещания («сделаю», «пришлю», «беру на себя»), поручения
(«на тебе», «за тобой»), договорённости, сроки. Каждая найденная фраза обязана
оказаться в задачах, решениях, вопросах, идеях — или быть осознанно отброшена.
Ни одна не теряется молча.

**Чек-лист качества (9) с жёстким правилом:** не прошёл блок «Достоверность» —
исправь до выдачи. Проверки конкретные и машинные: число задач совпадает со
строкой «Всего задач: N», исполнитель и контролёр — разные люди, не больше 30%
задач с меткой 🔴.

**Эскалация (7.3).** Отдельной строкой предупредить, если:
больше 30% задач без исполнителя или срока («встреча прошла без чётких
договорённостей»); на одном человеке 3+ горящих задачи («перегруз: имя»);
задача-блокер имеет срок позже зависящей от неё («конфликт сроков»).
Это уже не суммаризация, а контроль качества самой встречи.

**Разделение «факты, а не оценки».** «Срок не назван» — можно. «Мария уходит от
ответственности» — запрещено. Снимает главный риск авто-протокола: обидеть
человека формулировкой, которую он не произносил.

**Учёт специфики транскрибаций (3.5).** Ошибки распознавания имён, безымянные
спикеры, повторы одной задачи («бери самую конкретную формулировку и самый
поздний срок»), отмены («не, забудь» — задача не попадает в таблицу).

**Краевые случаи в примерах.** Текст без задач, запрос не по теме, попытка
сменить роль. Большинство промптов обрывается на счастливом пути.

**Мелочи, выдающие практику.** Запрет расшифровывать инициалы ФИО. Запрет
ASCII-арта. Отдельный формат для мессенджера, потому что таблицы в Telegram
ломаются. Правило не тащить суммы и телефоны в пересылаемую сводку.

## Чего в нём нет

**Способа доказать, что он лучше.** Ни тестового набора транскрибаций, ни
замеров, ни сравнения с наивным промптом. При 733 строках это главный пробел:
улучшать документ такого размера вслепую невозможно — любая правка меняет
поведение непредсказуемо.

**Версии.** Нет ни номера, ни даты, ни истории изменений. Автор сам сказал со
сцены, что «правила промптинга поменялись» — значит документ живёт и
переписывается, но какая это ревизия и что в ней изменилось, пользователь не
узнает.

**Экономики контекста.** 58 КБ (~15 тыс. токенов) уходят в окно при каждом
запросе, вручную, перед каждой транскрибацией. На бесплатном тарифе это прямо
конкурирует с объёмом самого разбираемого текста.

**Автоматизации.** Промпт — лист бумаги. Добыть транскрипт, перенести его,
вставить промпт, забрать результат, разослать — всё руками.

## Сравнение с нашим подходом

| | Их схема | Наша |
|---|---|---|
| Захват звука | Бот Read AI в Zoom/Teams | OBS на mac-work, любой источник, включая чужие эфиры |
| Распознавание | Облако (Read AI, «Диктуй») | Локально: faster-whisper large-v3-turbo на ubuntu-home |
| Приватность | Запись и внутренние цифры уходят внешнему сервису и в DeepSeek | Звук не покидает свои машины |
| Перенос текста | `Ctrl+A`/`Ctrl+C` руками | `live_tail.sh`, автоматически, блоками по 15 с |
| Разметка спикеров | Человек пишет «Спикер 1 — Антон» первой строкой | Две дорожки OBS + диаризация sherpa-onnx |
| Живой режим | Нет, разбор после встречи | Блоки прилетают в сессию каждые 30 с, можно подсказать в эфире |
| Правила разбора | **733 строки проработанного промпта** | Лист ожидания + моя добросовестность |
| Проверяемость вывода | **Цитата-основание под каждой задачей** | Нет: выводы проверяются перечитыванием конспекта |
| Контроль качества | **Чек-лист + эскалация** | Нет |
| Версионирование правил | Нет | Файлы под гитом, semver по Factor 2 |

Коротко: **мы сильно впереди по добыче данных и приватности, они впереди по
дисциплине разбора.** Это дополняющие сильные стороны, а не конкурирующие.

Наша слабость конкретна. Сводка груминга от 06.10 содержит выводы вроде
«развилка — блокер решения по квартальной цели», которые верны, но ничем не
подтверждены внутри самого документа: чтобы проверить, надо перечитать 286
строк конспекта. У них этот класс проблем закрыт одной строчкой правил.

## Что берём себе

Три механизма, в порядке отдачи:

1. **Цитаты-основания.** Каждый пункт сводки — с цитатой из конспекта и
   таймкодом. Таймкод у нас уже есть в каждой строке, это дешевле, чем у них.
2. **Чек-лист достоверности перед выдачей сводки.** Не выдумано ли имя, есть ли
   основание у каждого пункта, помечено ли выведенное.
3. **Эскалация.** Задачи без исполнителя и срока, перегруз человека, конфликт
   сроков. На груминге 06.10 такой конфликт был (срок 15 октября против
   согласования «ответ раз в сутки»), я его заметил устно, но в сводку как
   отдельный сигнал не вынес.

Плюс две структурные идеи:

4. **Справочник команды** (их 3.6) — постоянная таблица участников: имя,
   варианты написания, роль, зона ответственности. Закрывает сразу две наши
   дыры: исправление имён после распознавания и подстановку имён в диаризацию
   вместо `Speaker_00`.
5. **Форматы под канал** — сводка для мессенджера без таблиц. У нас инжект
   в Happy и отправка в VK, таблицы там тоже разъезжаются.

Чего **не** берём: ролевую преамбулу «ты — секретарь-протоколист», метафоры,
раздел про тон. Для агента, который и так работает в нашем контуре с готовыми
правилами, это чистый расход контекста.

## Вывод

Промпт сделан человеком, который много раз получал плохой результат и закрывал
дыры по одной. Это видно по тому, какие случаи предусмотрены. Методическая
рамка — ISO 9000, автор назвал её сам: отсюда критерии приёмки,
прослеживаемость и формулировка «нарушение правила = брак».

Копировать его целиком не нужно и вредно: половина объёма — обслуживание
ручного сценария «человек в чате», которого у нас нет. Нужны три механизма
проверяемости, и их стоит записать в наш промпт сводки — коротко и под гитом.
