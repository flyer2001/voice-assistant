# Инцидент 2026-10-23: 15 минут эфира без распознавания

**Что потеряли:** живое распознавание встречи по качеству с 00:09:00 до
00:24:30. Текст восстановлен постфактум из файла записи, в чате во время
эфира этих блоков не было.

**Что НЕ потеряли:** саму запись. `.mov` на mac-work цел, догон из файла дал
32 блока, они влиты в конспект.

## Хронология

| Время | Событие |
|---|---|
| 08:15, 08:36, 08:56 (часы хоста) | ubuntu-home трижды уходит в `PM: suspend entry (deep)` по простою |
| 10:49 (часы VDS) | хвост поднят, запись подхвачена, распознавание идёт |
| 10:56:21 VDS = 08:56 хоста | первая `ОШИБКА whisper HTTP 000` — ровно минута засыпания |
| 10:56 — 11:12 | хвост жив, пишет ошибку на каждый чанк, в чат не уходит ничего |
| ~11:12 | Sergey в чате: «ты чего остановился» |
| 11:12 | WoL, `PM: suspend exit`, whisper 200, распознавание продолжается с 00:25:00 |
| 11:14 | `sleep.target`, `suspend.target`, `hibernate.target`, `hybrid-sleep.target` замаскированы |

## Причина

ubuntu-home засыпала по простою. Sleep не был замаскирован, хотя это
известная грабля проекта — она записана в памяти как
`reference_ubuntu_home_sleep_breaks_cuda` и в
[live-transcribe.md](live-transcribe.md).

Сон приходит **по простою**, а не по расписанию: между чанками хвост молчит
10–30 секунд, этого хватает. Поэтому засыпание посреди эфира — не
случайность, а норма для незамаскированного хоста.

## Почему заметили только от человека

Два отдельных пробела, и второй дороже первого.

1. **Нянька этого не ловит.** `nanny.sh` следит за живостью `live_tail.sh`.
   Хвост был жив и исправно работал — он честно писал в лог «ОШИБКА whisper
   HTTP 000» на каждый чанк. С точки зрения няньки всё в порядке.
2. **Молчание в чате неотличимо от тишины в комнате.** Когда распознавание
   падает, в чат не приходит ничего — ровно как если бы на встрече никто не
   говорил. Пятнадцать минут это выглядело как «эфир идёт, просто пауза».

Доказательство работы, записанное в `prepare-to-rec` («не живой процесс, а
строка `N символов`»), проверяется **один раз на старте**. После старта за
этим никто не следит.

- Sleep на ubuntu-home замаскирован (4 target'а).
- Провал догнан из файла, конспект склеен по таймкодам, в сводке и в
  `INDEX.md` помечено, какой кусок восстановлен постфактум.

## Что осталось сделать

- [ ] **Нянька должна бить в чат на серию HTTP 000.** Порог — 3 подряд
      (полторы минуты): меньше похоже на сетевую рябь, больше уже потеря
      эфира. Текст сообщения должен содержать таймкод, с которого
      распознавание встало, чтобы догон был точным.
- [ ] **Проверять sleep в pre-flight скилла**, а не надеяться на память:
      `ssh ubuntu-home 'systemctl is-masked sleep.target'`. Не masked —
      маскировать до подъёма хвоста.
- [ ] Проверить, живёт ли маскировка после переключения в Windows и обратно
      (`os-switch.sh`). Если ОС переустанавливает target'ы — встроить
      маскировку в сам переключатель.
