# Переключение домашнего ноутбука с VDS

[README — вход](../README.md) · [Индекс](INDEX.md) · [Карта размещения](where-runs-what.md)

По просьбе Sergey 06.11 добавлены короткие команды в PATH VDS:

- `winup` — поднять Windows и дождаться SSH-готовности.
- `windown` — вернуть Ubuntu и дождаться SSH-готовности.
- `winup --dry-run` / `windown --dry-run` — показать команду без действий.

Это тонкие точки входа к существующему
`/root/projects/agentops/bin/os-switch.sh`; логика питания, аренды,
проверки интерактивного пользователя и ожидания остаётся у agentops.
Команды не создают сессий и не останавливают tmux. Время загрузки самой
ОС не сокращают, но убирают ручную последовательность проверок и переключения.
Готовность Ubuntu по SSH не доказывает готовность Whisper — для неё нужен
реальный фрагмент распознавания.

На mac-work `~/bin/winup` и `~/bin/windown` идут через SSH на VDS и
принудительно берут аренду на имя Sergey: это команды самого человека.
VDS-команды по умолчанию соблюдают аренду и не выдают агента за Sergey.
Явный `--force` передаётся существующему переключателю; агент применяет его
только при разрешении владельца на такое переключение, не для обхода отказа.
Имя держателя/причину можно передать стандартными `HOST_LEASE_HOLDER` и
`HOST_LEASE_REASON` существующего переключателя.

Исходники коротких входов: [winup](../scripts/winup), [windown](../scripts/windown).
Установка: `/usr/local/bin/winup` и `/usr/local/bin/windown` ссылаются на них.
Изменений в репозитории agentops нет. Тесты подменяют только внешнюю границу
OS-switch: `python3 scripts/test_home_os_shortcuts.py`. Реальные переключения
ради приёмки установки не выполнялись.

Короткие входы созданы в voice по прямому поручению Sergey для VDS;
общий движок переключения и его дальнейшее обслуживание остаются у agentops.
