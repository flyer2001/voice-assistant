# Тонкий голосовой клиент на телефоне: Zello против SIP

Ресёрч 2026-10-04, по просьбе Sergey'я. Вопрос: чем заменить колонку и
отложить разработку своего носимого девайса, используя iPhone 13 mini как
тонкий клиент.

**Вывод: SIP — то, что закрывает его сценарий целиком, Zello — то, что
проверяется за вечер. Начинать стоит со спайка Zello, целиться в SIP.**

## Что уже есть и чего не хватает

Навык Алисы работает (см. [alice-skill-input.md](alice-skill-input.md)):
короткая команда голосом, ответ голосом через очередь, пуш звуком через
сценарий умного дома. Не закрыто:

- **пауза ~2 секунды обрывает реплику** — длинный монолог не продиктовать,
  это ограничение платформы, обойти нечем;
- **нет кнопки** — только голосовая активация, каждый заход с именем навыка;
- **вне дома колонка бесполезна**, а в приложении Яндекса пуш не приходит:
  сценарий целится в колонки, не в телефон.

## Zello

**Чем хорош.** Готовое приложение, PTT в фоне — его прямое назначение, они
перешли на apple'овский PushToTalk framework. Есть официальный Channel API:
WebSocket `wss://zello.io/ws`, Opus, SDK под iOS, Android и веб.

**Чем плох.**

- **Half-duplex.** Это рация: нажал, сказал, отпустил. Длинный диалог с
  перебиванием не выйдет, и это ровно то, что Sergey называет «длинными
  диалогами».
- **Серверная часть у бесплатного тарифа урезана.** В документации прямо:
  server-side API доступен владельцам Zello Work, а для бесплатного
  приложения — «Channels SDK и Channels API с ограниченной
  функциональностью». Что именно урезано, по доке не понять — выясняется
  только пробой.
- **JWT обязателен.** Бесплатный аккаунт требует подписанный RS256-токен;
  issuer и приватный ключ выдаются в кабинете разработчика. Выданный
  sample-токен живёт 30 дней и для прода не годится — нужен свой выпуск
  токенов на сервере.
- **Подключение к нескольким каналам — только Zello Work.**

**Цена входа:** регистрация в кабинете разработчика, выпуск ключей, бот на
VDS. Вечер, если бесплатный тариф не упрётся в ограничения.

## SIP

**Чем хорош.**

- **Фон гарантирован системой**, а не настройкой приложения: это настоящий
  звонок через CallKit, экран гасится, звонок живёт часами.
- **Full duplex** — непрерывный разговор, перебивание, паузы на подумать.
  Ограничения Алисы с её двумя секундами тут нет вовсе.
- **Проводная гарнитура** работает как в обычном звонке — правило «без
  Bluetooth у головы» соблюдается.
- **Зрелая обвязка для агента.** Asterisk + ARI и ExternalMedia по RTP —
  готовый путь: аудио в STT, ответ через TTS. Есть открытые проекты ровно
  под это, с модульными провайдерами (локальный Vosk/Piper либо облако).
  Сообщество сообщает о задержке «рот-в-ухо» ниже 250 мс при потоковой
  передаче токенов из LLM прямо в синтез.
- **Клиенты живые.** Groundwire — платный, интегрирован с CallKit, входящие
  через свой push-сервис без разряда батареи. Linphone — бесплатный,
  открытый, по замерам экономичнее прочих на удержании регистрации
  (~3.9%/час в простое за счёт 120-секундных OPTIONS вместо 30-секундных).

**Чем плох.** Это инфраструктура: Asterisk на VDS, SIP-регистрация, TLS и
SRTP, NAT. Не вечер.

## Сравнение под его сценарий

| | Алиса (есть) | Zello | SIP |
|---|---|---|---|
| длинный монолог | нет, 2 с обрывают | нет, half-duplex | **да** |
| фон на iOS | не нужен | да, PTT framework | **да, системой** |
| кнопка | нет | да, экранная | в звонке не нужна |
| вне дома | нет | да | **да** |
| проводная гарнитура | — | да | **да** |
| агенту влезть в канал | через очередь | Channel API | **ARI/RTP** |
| цена | сделано | вечер + ключи | дни |
| риск | платформа Яндекса | урезанный free | своё, рисков нет |

## Что делать

1. **Спайк Zello, вечер.** Завести ключи, поднять бота, проверить **ровно
   одно**: умеет ли бесплатный аккаунт принимать и отдавать голос через
   Channel API. Если упрётся в Zello Work — затея закрыта, и это дешёвое
   закрытие.
2. **Спайк SIP, вечер.** Asterisk на VDS, Linphone на телефоне, обычный
   звонок до эхо-теста. Проверяется ровно одно: держится ли звонок в фоне
   при погашенном экране и не рвёт ли его NAT.
3. **Решение по результатам.** Если SIP-звонок держится — он и есть цель,
   Zello остаётся на «нажал-сказал без звонка».

Спайки независимы и оба на вечер. Сначала спайк, потом план и TDD —
правило, купленное этой сессией: сценарии умного дома мы проверили руками
за две минуты и выяснили, что триггер только по устройству. Начни мы с
плана на виртуальном датчике — выкинули бы вечер.

## Чего не рассматриваем

- **TeamSpeak** — клиент живой, но воткнуть агента в канал нечем: аудио-API
  нет ни в TS3, ни в TS5, аудиоботы жили на заброшенном SinusBot.
- **Mumble** — сервер и боты отличные, но официальный iOS-клиент мёртв с
  2017, в App Store только сторонние пересборки.
- **Своё приложение** — с iOS 26 все PTT-приложения обязаны идти через
  apple'овский PushToTalk framework, `unrestricted-voip` выпилен из SDK.
  Делается, но это ровно та разработка, которую Sergey откладывает.
