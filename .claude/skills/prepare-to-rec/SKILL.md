# prepare-to-rec

Полная механика, грабли и диагностика — `~/.claude/docs/live-transcribe.md`.
Здесь только последовательность и то, чего в доке нет.

## 1. Pre-flight — три проверки одной командой

```bash
/root/projects/agentops/bin/detect-home-os.sh
curl -s -o /dev/null -w "whisper:%{http_code}\n" --max-time 10 http://192.168.88.13:8000/health
~/projects/assistant/scripts/inject/resolve-happy-sid.sh
ps -eo pid,ppid,lstart,cmd | grep -E "[l]ive_tail\.sh|[n]anny\.sh"
```

- `windows` или `offline` → переключить и **дождаться**:
  ```bash
  HOST_LEASE_HOLDER=voice /root/projects/agentops/bin/os-switch.sh ubuntu --wait
  ```
  Отказ по аренде называет держателя — договариваться, не форсить: `--force`
  аренду не снимает, а форс из Windows может оставить машину выключенной.
  `--wait` не вернулся за ~5 минут, или машина не поднимается, или 22-й порт
  закрыт — **стоп и к Sergey**. Различать: не пингуется (железо), порт закрыт
  (ОС грузится или не та), `/health` молчит при живом ssh (сервис/CUDA).
- `whisper` не 200 или таймаут → **хвост не поднимать и няньку тем более**:
  нянька будет бесконечно рестартить падающий хвост, лог засрётся, а вид будет
  как у работающего. Сказать в чат «не стартуем, пока `/health` не 200» и
  лечить по разделу про CUDA в доке.
- Чужой хвост или нянька с прошлой сессии → гасить, **но сначала убедиться, что
  он чужой**:
  ```bash
  ps eww -p <PID> | tr ' ' '\n' | grep -E "VOICE_INJECT_SID|VOICE_REC_DIR"
  ```
  Свой — тот, у кого `VOICE_INJECT_SID` равен твоему sid. Чужой sid — гасить по
  pid, иначе его блоки уедут в архивную сессию, а рядом с твоим хвостом дадут
  дубли. **Без этой проверки не убивать**: `pkill -f "live_tail.sh mac-work"`
  накрывает все хвосты на этом хосте, включая чужой рабочий.

## 2. Поднять хвост и няньку

sid подставить свой, из `resolve-happy-sid.sh`. `VOICE_CHUNK_S=30` — блоки по
30 с: на 15 с половина фраз рвётся на границе.

```bash
setsid nohup env \
  VOICE_REC_DIR='$HOME/Movies' \
  VOICE_CHUNK_S=30 \
  VOICE_INJECT_EVERY=1 \
  VOICE_INJECT_SID=<свой sid> \
  VOICE_PROMPT_FILE=/root/projects/voice/bench/work/prompt.txt \
  /root/projects/voice/backend/voice-service/deploy/live-transcribe/live_tail.sh \
  mac-work /srv/voice-private/live >> /srv/voice-private/live/tail.log 2>&1 < /dev/null &

cd /root/projects/voice && setsid nohup env \
  VOICE_INJECT_SID=<свой sid> VOICE_CHUNK_S=30 VOICE_INJECT_EVERY=1 \
  VOICE_PROMPT_FILE=/root/projects/voice/bench/work/prompt.txt \
  backend/voice-service/deploy/live-transcribe/nanny.sh \
  >> /srv/voice-private/live/nanny.log 2>&1 < /dev/null &
```

`bench/work/prompt.txt` — рабочая терминология Авито. Другая тема — свой файл.

⚠️ **Хвост берёт любой свежий `.mov` (фильтр `-mmin -10`) с позиции 0.**
Если только что закончилась предыдущая запись, он подхватит её и перегонит
заново — это десятки дублей в чат и мусор в конспекте. Перед подъёмом хвоста
посмотреть, что вообще свежего лежит на маке, и закрыть всё лишнее маркером:

```bash
ssh mac-work 'ls -lt ~/Movies/*.mov | head -3'
touch "/srv/voice-private/live/.done-<basename прошлой записи>.mov"
```

Имя маркера — ровно `.done-` + имя файла с расширением, как его печатает `ls`.
Больше одного свежего `.mov` (тестовая запись, чужой клип) — закрыть маркером
каждый, кроме текущего: иначе хвост возьмёт первый найденный, а не тот,
который нужен. Маркер `.done-` — единственный штатный способ сказать «эту не
трогай».

⚠️ **Два процесса `live_tail.sh` — не всегда дубль, и ppid этого не решает:**
`setsid` делает ppid 1 и родителю, и переподхваченному процессу. Решает env —
дубль это два процесса с **одинаковым `VOICE_INJECT_SID`** и разными позициями
в логе; дочерний сабшелл живёт под pid родителя и своего env не меняет.
Проверять через `ps eww -p <PID>`, как выше. Вслепую не гасить.

## 3. Доказать, что транскрипция идёт

Живой процесс доказательством **не является**. Доказательство — строка
`N символов` в логе и блок с текстом в чате.

```bash
tail -3 /srv/voice-private/live/tail.log
```

Ждёт — `жду новой записи...`. Подхватил — `запись: /Users/.../<имя>.mov`,
дальше пойдут чанки.

Если OBS ещё не запущен — дождаться подхвата, не опрашивая лог в цикле:

```bash
# run_in_background: true
for i in $(seq 1 30); do
  grep -q "запись: /Users" <(tail -5 /srv/voice-private/live/tail.log) && exit 0
  sleep 10
done
echo "ПОДХВАТА НЕТ 5 МИНУТ — в диагностику"; exit 1
```

**Потолок обязателен.** Бесконечный `until` переживёт и смену формата строки, и
ротацию лога, и тогда «тишина в чате» будет означать не «эфир не начался», а
«вейтер висит». Вышел таймаут — сказать Sergey и идти в диагностику, не
перевзводить вейтер молча.

Нет текста за две минуты после начала речи — идти в диагностику по доке,
а не ждать дальше. Серия строк `тишина` подряд — тоже повод идти, а не ждать.

## 3.5. Проверить уровень звука по дорожкам

Делать **сразу после подхвата**, не дожидаясь жалоб на пустой конспект.
Хвост читает дорожку 1 и молчит, если звук ушёл в другую.

```bash
REC="/Users/sgpopyvanov/Movies/<имя записи>.mov"
for T in 0 1; do
  echo -n "дорожка $((T+1)): "
  ssh mac-work "export PATH=/opt/homebrew/bin:\$PATH; \
    ffmpeg -t 60 -i '$REC' -map 0:a:$T -af volumedetect -f null -" 2>&1 \
    | grep mean_volume || echo "нет дорожки"
done
```

- **около −30 dB** — речь есть, всё нормально.
- **−91 dB** — дорожка пустая. Это не тишина в комнате, а мёртвый источник.

Что делать по результату:

| Дорожка 1 | Дорожка 2 | Действие |
|---|---|---|
| есть звук | есть звук | ничего, `VOICE_TRACKS=2` даёт разметку `эфир:` / `Сергей:` |
| есть звук | пустая / нет | обычный случай, `VOICE_TRACKS=1` |
| **−91 dB** | есть звук | перезапустить хвост с `VOICE_TRACKS=2` и **сказать Sergey**: собеседников нет, пишется только микрофон |
| −91 dB | −91 dB | звука нет вообще, в OBS мёртвые оба источника — не продолжать, идти в диагностику |

⚠️ **Пустая первая дорожка — это потерянный эфир, а не косметика.** Так 22.10
потеряли первые 6 минут груминга: источник «Захват звука macOS» отвалился при
подключении наушников, участников не слышно нигде (их звук уходит в наушники,
микрофон через воздух их не берёт). Чинится в микшере OBS: включить источник
или удалить и добавить заново — macOS теряет разрешение на захват при смене
аудиоустройства.

⚠️ При `VOICE_TRACKS=2` в конспект попадает **и то, что микрофон слышит в
комнате**: бытовые разговоры, домашние. В сводку их не тащить, брать только
дорожку `эфир:`.

⚠️ `nanny.sh` наследует `VOICE_TRACKS` из своего окружения (правка 22.10) —
поднимать её тем же env, иначе при перезапуске вернётся дорожка 1 и снова
тишина, а вид будет как у живого хвоста.

## 4. Сказать в чат

Только после того, как увидел реальный текст (или, если эфир ещё не начался,
строку `запись: ...`):

> 🔴 **ЗАПИСЬ И ТРАНСКРИБАЦИЯ ЭФИРА ЗАПУЩЕНА**

Рядом, коротко: имя записи, размер чанка, что sid сверен, что хвост один и
нянька на месте, **уровень звука по дорожкам**, путь к конспекту.

Если эфир ещё не начался, так и сказать: подхват есть, текста пока нет,
первый блок покажу.

## 5. Дальше — режим слушателя

Блоки не комментировать построчно. Вопросы Sergey'ю — **текстом**, не голосом:
он в эфире. Попадания — в `/srv/voice-private/live/questions.md`.

Галлюцинации на тишине («Спасибо», «Продолжение следует», перечисления имён,
титры несуществующих авторов) — не реплики, не разбирать.

Разбор после эфира — скилл `meeting-digest`.
