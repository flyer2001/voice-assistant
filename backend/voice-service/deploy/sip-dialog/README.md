# SIP: локальные команды только во время звонка

[Индекс](../../../../docs/INDEX.md) ·
[Исследование](../../../../docs/thin-voice-client-research.md#голосовые-команды-паузы-и-тихая-индикация--исследование-1611)

Экспериментальная реализация поручения Sergey 16.11.2026. Номер 7304
начинает в паузе. После загрузки детектора — короткий тихий сигнал.

- **«Голосовой помощник, слушай»** — сигнал начала, затем запись.
- **«Голосовой помощник, пауза»** — прервать текущую озвучку/запись и
  не передавать обычную речь в STT или агенту. Команда работает и при ответе.
- В паузе и ожидании — мягкий пульс через 45 с, без наложения на ответ.
- Устаревший ответ после паузы не возобновляет озвучку. Внешние сообщения
  привязаны и к вызову, и к его `epoch`, а не только к общему номеру.

Пауза не отменяет уже отправленное задание агента; его результат остаётся
в чате. Полное завершение записи пока прежнее: три секунды тишины, `#`
или 120 с, предупреждение на 110 с. Предел звонка — 50 минут.
Фразы/период пульса — в `settings.example.json`; runtime-копия `settings.json`
читается новым вызовом. Текущая реализация требует Python 3.12: `audioop`
для 8→16 кГц отсутствует в Python 3.13, эту замену пока не делали.

## Жизненный цикл и границы

`launch.py` запускается только приложением AGI уже отвеченного канала.
Он проверяет AGI identity и `CHANNEL STATUS=6`, затем создаёт один дочерний
`worker.py`. Родитель не импортирует Vosk. Дочерний процесс загружает
модель и открывает один временный TCP-порт на 127.0.0.1. UUID AudioSocket
проверяется перед аудио. Asterisk переключает канал в штатный `AudioSocket`.

После отбоя/ошибки/EOF процесс закрывается; AGI ждёт короткое штатное
завершение и при необходимости адресно завершает только своего ребёнка.
Linux `PR_SET_PDEATHSIG` дополнительно завершает ребёнка, если AGI погибает
без выполнения cleanup; потерянный родитель проверяется до загрузки модели.
Постоянного listener, systemd socket/unit или Vosk-сервера нет. Без вызова
нет процесса, загруженной модели и периодического распознавания. Файлы
модели остаются на диске; OS может сохранять их страницы в освобождаемом кэше.

Основной Whisper и SpeechKit TTS переиспользуются через существующий
приватный UNIX-брокер. [vendor:codex] Адрес и отправка в native-чат находятся
в этом брокере, а не в командном детекторе. Публичный backend-контракт
не менялся. Брокер/Asterisk и удержание домашней машины — существующие
отдельные компоненты; нулевой idle CPU ниже относится к новому детектору.

`control.py` — состояния/аудио; `detector.py` — локальная Vosk с короткой
грамматикой и `[unk]`; `worker.py` — AudioSocket и асинхронная граница брокера;
`launch.py` — жизненный цикл; `push.py` — проверка вызова/поколения уведомления.
В паузе обычная речь не пишется в речевые файлы или логи. Журнал содержит
только состояния, счётчики и ресурсы. Основной STT получает звук только
после стартовой команды и сигнала. Изменение словаря не равно обучению на
голосе Sergey: ложные срабатывания на его гарнитуре ещё нужно проверить.

## Ресурсы, измеренные 16.11

VDS: 2 vCPU, 4 GiB RAM. CPU приведён в процентах **одного** ядра,
а не от суммарной мощности двух ядер. Это добавка call-worker.

| Режим | CPU одного ядра | Пиковый RSS | Наблюдение |
|---|---:|---:|---|
| Нет вызова | 0% | Процесса нет | После отбоя отсутствуют worker и его порт; существующий Asterisk отдельно ~1,3% в 10-секундном окне |
| Пауза/тишина, двусторонний поток 25 с | 2,32% | 211,5 MiB | Ноль обычных STT-запросов, пульс работает |
| Речь + озвучка + стоп, поток 27 с | 6,55% | 214,9 MiB | Одно обращение к подменённой внешней границе; стоп через 0,546 с после конца полной фразы, выход далее тихий |
| Реальный TLS/SRTP SIP, короткие вызовы | ~3,8–5,5% | 214,6 MiB | Один старт и стоп; нет обычного STT; ребёнок исчез после отбоя |

Первичная загрузка в SIP: около 4–6 с wall / 2–2,6 с CPU при существующем
ограничении Asterisk 50% одного ядра. Общий потолок CPU не повышен.
Для загрузки библиотеки лимит потоков службы поднят 64→128 (на 64
зафиксирован `pids.events max`), memory ceiling 256→512 MiB. Это верхние
границы, а не постоянно потребляемые ресурсы. Общий наблюдённый memory peak
службы на проверке был около 219 MiB, после отбоя около 19 MiB.

[Машинные результаты](resources-2026-11-16.json). Диалоговый поток использует
реальную Vosk и реальные звуковые файлы; подменена только внешняя граница
основного STT/агента, поэтому её стоимость не включена в CPU детектора.
Это короткие контролируемые записи, не измерение ложных срабатываний
на улице и не замер батареи iPhone/Shokz. Уровень пульса надо оценить в
реальной гарнитуре. Его частота/громкость пока не являются обещанием экономии.

## Проверки

```sh
PYTHONPATH=backend/voice-service/deploy/sip-dialog \
  python3 -m unittest discover -s backend/voice-service/deploy/sip-dialog/tests

# Намеренный ограниченный аудиотест, не постоянно работающая служба:
<control-venv>/bin/python3 backend/voice-service/deploy/sip-dialog/bench.py \
  --assets <probe-dir> --mode paused --seconds 25 --out <result.json>
```

16 проверок: состояние паузы, точная команда, сигнал до записи, тишина без
decoder-вызовов, сохранение хвоста для endpointing, прерывание и старый
результат, AudioSocket fragmentation, запуск без канала и отложенные push.
Реальные синтетические русские команды проверены и в Vosk, и локальным
зашифрованным SIP-вызовом с обычным G.711. На границе AudioSocket дополнительно
проверено, что звук прекращается после стопа. Во время вызовов создавались
разные PID модели; за вызовом процесс не сохраняется.

## Runtime и откат текущей пробы

Исходник — этот каталог. В текущей приватной пробе он копируется в
`/var/tmp/voice-sip-probe.qBbfRrHl/sip_control/`; venv и официальная модель
`vosk-model-small-ru-0.22` находятся рядом вне Git. В namespace Asterisk
это `/run/voice-sip-probe-assets/`. Устанавливать библиотеки в системный
Python не требуется. Нужны `res_audiosocket.so`, `app_audiosocket.so`,
собранные против той же Asterisk 20.22, и существующий голосовой брокер.

Новая dialplan-строка 7304:

```text
AGI(/run/voice-sip-probe-assets/sip_control/launch.py)
```

Старый `dialog_call.py` сохранён. Снимки dialplan/modules:
`probe-config/extensions.conf.before-control-20261116` и
`probe-config/modules.conf.before-control-20261116`. Чтобы откатить новые
вызовы, восстановить только прежнюю AGI-строку и перезагрузить dialplan.
Действующий вызов сначала штатно закончить; чужие процессы/hold не трогать.
Снижать memory/tasks ceilings следует только после исчезновения worker.
Удалять модель или исходные записи для отката не требуется.

Отложенный producer должен сохранить `call_id` и `epoch` при постановке
задания и передать `--epoch` в runtime `sip_push.py`. Новый `schedule_demo.py`
текущей пробы это делает. Обычная речь и текст агента не исполняются как
команды управления оболочкой; команды ограничены двумя состояниями голоса.
