## Паттерны и что о них известно

| Паттерн | Что известно | Оценка для Sergey |
|---|---|---|
| orchestrator-worker | Anthropic: lead-агент раздаёт параллельные поиски субагентам, сам синтезирует. ~15x токенов к обычному чату, ~4x у обычного агента [Р] https://www.anthropic.com/engineering/multi-agent-research-system. У OpenAI это «agents as tools»: менеджер владеет финальным ответом [Р] https://developers.openai.com/api/docs/guides/agents/orchestration.md | известное |
| planner-executor | Нет отдельной рекомендации держать planner-агента; OpenAI допускает и план от модели, и оркестрацию кодом [Р] https://openai.github.io/openai-agents-js/guides/multi-agent/ | известное (Plan mode) |
| evaluator-optimizer | Генератор + критик с лимитом итераций; работает при проверяемых критериях [Р]. | известное (TDD-цикл, Ralph) |
| map-reduce | Независимые куски, потом свёртка; риск дублей и потери нюансов [Р, без первоисточника, общая оценка] | известное |
| router / handoff | Специалист забирает разговор (handoff) vs менеджер остаётся ответственным [Р] | известное, мало нужно в соло-работе |

Где параллельность помогает: независимые подзадачи с чётко поставленным заданием. Где вредит: последовательные шаги, общие файлы, частая связь между агентами; OpenAI прямо просит согласовывать агентов, правящих одни файлы [Р] https://developers.openai.com/api/docs/guides/agents-api/multi-agent.

НЕ подтверждено: perplexity не нашёл Cognition «Don't build multi-agents» и исследование Google/MIT про масштабирование. Цифры оттуда не приводить без проверки.

Скептик [С]: все пять названий это while/if/for/retry с логом; без типизированных артефактов между агентами и автопроверок это переименованный цикл. 15x это плата за контрольный поток, а не ROI. Замеры ускорения обычно не учитывают планировщика, слияние, rate limits и ревью человеком. Базовая линия, которой не хватает: один сильный агент с асинхронными инструментами при равном токен-бюджете.

## Скиллы: что это технически

- Каталог с `SKILL.md`: YAML (`name`, `description`, опционально `license`, `compatibility`, `allowed-tools`) + markdown + опционально скрипты и справочники [Р] https://agentskills.io/skill.md.
- Прогрессивное раскрытие: в контекст сначала только name+description, тело грузится при совпадении, файлы по ссылкам читаются по ходу [Р].
- Открытый формат, путь `.agents/skills/` как кросс-клиентный [Р] https://agentskills.io/home.
- Отличия: skill учит рабочему процессу; MCP даёт доступ к инструментам и данным (протокол); CLAUDE.md/AGENTS.md это общий контекст проекта, грузится всегда. Сравнение с MCP и rule files у perplexity концептуальное, без первоисточников.
- Замеры, SkillsBench: curated skills +16.2 п.п. в среднем, 86 задач, 11 доменов, 7 конфигураций, разброс +13.6..+23.3 [Р] https://www.skillsbench.ai/skillsbench.pdf. Claude Code + Opus 4.5: 22.0% -> 45.3% [Р] https://www.skillsbench.ai/blogs/introducing-skillsbench. Версия 1.1: 33.9% -> 50.5%, 18 конфигураций [Р] https://www.skillsbench.ai/blogs/skillsbench-1-1. Self-generated skills: стабильной пользы нет; узкие скиллы лучше «всеобъемлющих» [Р, обзор] https://www.oreilly.com/radar/agent-skills-work-but-the-research-shows-most-teams-are-building-them-wrong/.
- Vercel «AGENTS.md vs skills»: perplexity не нашёл, цифр нет.
- Скептик [С]: технически это структурированный промпт; доказательство обратного требует абляций (порядок, длина, OOD, смена модели) и сравнения с одним длинным промптом. SkillsBench это даёт частично: curated vs self-generated.

## Стоп-критерии и бюджеты

- Agent SDK: `max_turns` (по умолчанию не задан; 0 = без лимита, не «ноль ходов»), `max_budget_usd` (не задан; включает субагентов; ход, пересёкший лимит, успевает завершиться, нужен запас; 0 отклоняется) [Р] https://code.claude.com/docs/en/agent-sdk/agent-loop, https://code.claude.com/docs/en/agent-sdk/configuration.
- Таймаут по времени и детект повторов вызовов: встроенных в SDK по источникам нет, это слой вызывающего [Р].
- Completion promise в Ralph-цикле: самоотчёт модели, не предохранитель [Р, согласуется с [С]].
- Статистики «сколько запусков уходит в цикл» публично нет [Р].

## Что было бы реально новым

- Устройство приёмки: как у Claude Code web / Codex cloud устроен гейт «что считать готовым» кроме человеческого ревью.
- Детект зацикливания по сигнатурам вызовов как готовый слой (у Sergey: hb таймаут + cost cap, но не детект повторов) [вывод по прочитанному, не проверено по коду].
- Изоляция секретов через прокси (креды вне песочницы): у Sergey воркеры на своих машинах с ssh-доступом, другая модель угроз.
- Абляции «один агент vs мульти» при равном бюджете, если спикер их покажет. Публичных пока не нашли.
- Надзор за in-process субагентом: у Sergey это известная дыра (в TASKS agentops); если спикер закрыл, это новость.
