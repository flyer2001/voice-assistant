# Plan — дайджест трендов GitHub (тема multi-agent)

Источник фактов: `out/research-notes.md`. План ему не противоречит: только REST Search API (не GraphQL), лимит search 30/мин, два запроса на прогон. Нуль npm-зависимостей. Один прогон.

## 1. Архитектура и файлы

Приложение — в подпапке `app/` демо-папки. Две части:

1. **Браузерная часть** — `app/index.html`: одностраничный HTML + инлайновый vanilla JS (без `<script src>`, без ES-модулей — при открытии по `file://` модули блокируются CORS политики `null`-origin; один файл работает по `file://` без сервера). Приложение стартует автоматически по `DOMContentLoaded`: рендерит каркас, показывает поле токена, после ввода токена сразу запускает сбор и рендер карточек. Предварительный запуск сервера не нужен.
2. **Node-часть** (проверка/артефакт state) — `app/collect.mjs` + небольшие модули `app/lib/*.mjs` (ролевое разделение, см. ниже), запускается одной командой `node app/collect.mjs`.

Модули (по ролям; в `index.html` — те же роли, но инлайновыми секциями с теми же алгоритмами, а в Node — импортируемыми `.mjs` ради тестов):

| Роль | Файл | Ответственность |
|---|---|---|
| Даты | `app/lib/date.mjs` | `dateSevenDaysAgo(now)` → `YYYY-MM-DD` (UTC, today − 7 дней). В браузере — та же функция инлайн. |
| Запросы | `app/lib/query.mjs` | `buildSearchUrl(category, d7)` — сборка URL с `encodeURIComponent`. |
| Очередь | `app/lib/queue.mjs` | единая последовательная очередь внешних запросов + retry (см. п.1.2). |
| Сортировка | `app/lib/sort.mjs` | `sortByStarsDesc(items)` — страховочная сортировка (см. п.4). |
| Рендер | `app/lib/render.mjs` | `renderCard(item)` → HTML-строка карточки; `renderSection(title, items)`; экранирование текста. В `index.html` — эквивалентная DOM-версия. |
| State | `app/lib/state.mjs` | чтение/валидация/запись `out/state.json` (курсоры — см. п.5). |
| Точка входа Node | `app/collect.mjs` | секреты из env → очередь → state.json (см. п.5). |
| Точка входа браузера | `app/index.html` | UI, темы, прогресс, поле токена, вызов тех же алгоритмов. |

### 1.1 Запуск по `file://`
- Открытие двойным кликом `app/index.html` → `fetch()` к `https://api.github.com` работает: GitHub REST отдаёт `Access-Control-Allow-Origin: *`, preflight `OPTIONS` для заголовка `Authorization` GitHub обрабатывает (факт research п.4; обязательная проверка при реализации — если браузер заблокирует запрос, это фиксируется как ошибка в UI, архитектура не меняется).
- Дата «7 дней назад» считается в рантайме, не хардкод `2026-10-07`.

### 1.2 Единая очередь внешних запросов (и в браузере, и в `collect.mjs`)
- Единственная очередь, последовательная: запросы ставятся в очередь и исполняются строго по одному (promise-цепочка). Других сетевых вызовов в приложении нет.
- Retry при HTTP `403` или `429`: пауза по заголовку `Retry-After` (секунды), если его нет — по `X-RateLimit-Reset` (unix-секунды минус текущее время, минимум 0). Максимум 3 ретрая на запрос, затем запрос считается упавшим.
- Иные ошибки (`401`, `422`, сетевые) не ретраятся, показываются в UI / пишутся в stderr.
- В `queue.mjs` `fetch` — инъектируемый параметр (по умолчанию глобальный `fetch`) — для тестов с подменённым fetch без сети.

### 1.3 Секреты
- **Node (`collect.mjs`)**: токен читается только из `process.env.GITHUB_TOKEN`. Если переменная отсутствует или пуста — скрипт сразу завершается с `exit code 1` и сообщением вида «Не задана переменная среды GITHUB_TOKEN. Задайте её, например: $env:GITHUB_TOKEN = "<токен>"». Никаких сетевых запросов до этой проверки.
- **Браузер**: переменные среды браузеру недоступны (факт research п.4). Компромисс, зафиксированный research: на странице masked-поле `<input type="password">` для токена; значение хранится только в переменной памяти JS-модуля; не пишется в localStorage/sessionStorage/URL/cookie; не попадает ни в один `console.log`; не вшито в код; после перезагрузки страницы вводится заново. В README показывается, как взять значение: в PowerShell выполнить `$env:GITHUB_TOKEN` и скопировать вывод в поле.
- Токен не логируется нигде: в сообщениях об ошибках — только HTTP-код и текст ошибки GitHub.

## 2. Данные

Только `GET https://api.github.com/search/repositories` (REST-only; GraphQL запрещён: fine-grained токен не имеет доступа к connection `stargazers`).

Два запроса (оба через очередь):
- «свежие»: `q = topic:multi-agent created:>=<d7>`
- «изменения»: `q = topic:multi-agent pushed:>=<d7>`

где `d7` — дата today − 7 дней в `YYYY-MM-DD` (UTC), вычисляется в рантайме. Параметры: `sort=stars&order=desc&per_page=12`. `q` — через `encodeURIComponent` (research п.1). Заголовки: `Authorization: Bearer <token>`, `Accept: application/vnd.github+json`, `X-GitHub-Api-Version: 2022-11-28`.

Из `items[]` используются поля (имена точные, research п.2): `full_name`, `html_url`, `description`, `stargazers_count`, `forks_count`, `open_issues_count`, `language`, `created_at`, `updated_at`, `pushed_at`, `owner.login`, `owner.avatar_url`, `topics`, `license.spdx_id` (license может быть `null`). Аватар репозитория = `owner.avatar_url` (отдельного аватара репозитория в API нет).

Лимиты: search 30/мин — двух запросов на прогон достаточно; поллинг запрещён.

## 3. UI (`app/index.html`)

- Две секции: «Свежие (созданы за 7 дней)» и «Изменения (push за 7 дней)», по 12 карточек.
- Сетка: ровно 3 карточки в ряд (`grid-template-columns: repeat(3, ...)`), контейнер сетки с ограниченной максимальной шириной (например `max-width: 960px`) и `margin: 0 auto` — ряды центрированы по горизонтали, не растянуты на весь экран.
- Карточка (обязательно): аватар `owner.avatar_url` (`<img>`), `full_name`, краткое описание, число звёзд.
- Клик по карточке разворачивает подробную информацию прямо внутри карточки (без модалок и переходов): полное описание, `language`, `forks_count`, `open_issues_count`, `created_at` / `updated_at` / `pushed_at`, `topics` (чипы), `license.spdx_id`, ссылка на `html_url` (`target="_blank"`).
- Темы: светлая (по умолчанию) и тёмная — переключатель (radio/checkbox), CSS-переменные на `:root` / `[data-theme="dark"]`. Выбор темы — только в памяти страницы (без localStorage, чтобы не расширять задачу).
- Прогресс загрузки: индикатор по числу завершённых шагов из 2 (запрос «свежие», запрос «изменения»); при отрисовке карточек прогресс отражает готовые секции. Отображается до/во время запросов.
- Обработка ошибок: `401` — «токен неверен или истёк, введите заново»; `403`/`429` — обработка очередью с ретраями (п.1.2), после исчерпания ретраев — сообщение о превышении лимита; `422` — сообщение о некорректном запросе; сетевая ошибка — соответствующее сообщение. Текст ошибки выводится в UI, без токена.
- Функций вне задачи нет (нет пагинации, фильтров, экспорта, автообновления).

## 4. Ранжирование

Основная сортировка — на стороне API: `sort=stars&order=desc` (research п.1). Страховка в JS: после получения `items` — повторная сортировка копии массива по `stargazers_count` по убыванию (`b.stargazers_count - a.stargazers_count`) перед рендером и перед записью в state. Обе категории ранжируются одинаково.

## 5. State-файл

Путь и формат вывода зафиксированы: **`out/state.json`** (в `out/` демо-папки), JSON UTF-8:

```json
{
  "generated_at": "2026-10-14T12:00:00Z",
  "since": "2026-10-07",
  "queries": { "fresh": "<q fresh>", "updated": "<q updated>" },
  "fresh":   [ { "full_name": "...", "html_url": "...", "description": "...",
                 "stargazers_count": 0, "forks_count": 0, "open_issues_count": 0,
                 "language": "...", "created_at": "...", "updated_at": "...",
                 "pushed_at": "...", "owner_login": "...", "owner_avatar_url": "...",
                 "topics": [], "license_spdx_id": "..." }, ... 12 ],
  "updated": [ ...те же поля, 12 ]
}
```

Курсоры состояния между запусками: `generated_at` + `since` (граница 7 дней) + сами `queries` — по ним видно, где и когда собран дайджест; при повторном запуске скрипт перезаписывает файл целиком (один прогон, инкрементальность не требуется).

Формирование: `node app/collect.mjs` (Node 20+, глобальный `fetch`):
1. Проверка `process.env.GITHUB_TOKEN` (п.1.3), иначе немедленный `exit 1` с сообщением.
2. `d7 = dateSevenDaysAgo(new Date())`, сборка двух URL.
3. Оба запроса — через единую очередь с retry (п.1.2).
4. Сортировка-страховка (п.4), маппинг item → плоская запись (поля выше), `slice(0, 12)` на категорию.
5. Запись `out/state.json` (`node:fs/promises`), `exit 0`.

Обязательная проверка при реализации: запуск `node app/collect.mjs` → код возврата 0, `out/state.json` существует, массивы `fresh` и `updated` непустые (research подтвердил: total_count 670 и 3462 — по 12 наберётся).

## Tests

`app/test/*.test.js`, запуск `node --test app/test` (или `node --test`). Нуль сети (везде подменённый `fetch`/фикстуры), секреты не читаются (env в тестах не используется; в тестах `collect`-функций токен передаётся фиктивной строкой в виде «FIXED», реальный env не трогается). Фикстура — `app/test/fixtures/search_response.json` (урезанная копия структуры ответа Search API: `total_count`, `incomplete_results`, `items[]` с полями из п.2).

Тест-кейсы:
1. **Курсор состояния** (`state.test.js`): запись объекта state во временный файл и чтение обратно — `generated_at`, `since`, `queries` сохранены; валидатор отвергает state без `since`/`fresh`/`updated`.
2. **Рендер по фикстуре** (`render.test.js`): `renderCard(item)` из фикстуры содержит `full_name`, `stargazers_count`, `owner.avatar_url` в `<img src>`; HTML-спецсимволы описания экранированы; `renderSection` даёт ровно 3 карточки на ряд (обёртки сетки) для 12 элементов.
3. **Retry очереди на подменённом fetch** (`queue.test.js`): фейковый `fetch` возвращает `403` с `Retry-After: 1`, затем 200 — очередь выполнила запрос дважды и вернула результат; `429` без `Retry-After`, но с `X-RateLimit-Reset` (unix-секунды) — пауза вычислена по reset; три подряд `403` без заголовков — ровно 3 ретрая, затем ошибка; `401` — без ретрая, одна попытка.
4. **Данные/сортировка/дата** (`query.test.js`, `sort.test.js`, `date.test.js`): `dateSevenDaysAgo` даёт `YYYY-MM-DD` ровно на 7 дней раньше (UTC); `buildSearchUrl` содержит `topic%3Amulti-agent`, `created%3A%3E%3D`, `per_page=12`; `sortByStarsDesc` упорядочивает фикстуру по убыванию звёзд.
5. **Запуск collect-скрипта** (`collect.test.js`): `spawnSync(node, [app/collect.mjs])` без `GITHUB_TOKEN` (пустой env) → код возврата ≠ 0 и в stderr сообщение про `GITHUB_TOKEN` (сеть не трогается, скрипт падает до запросов). Сетевой прогон со реальным токеном — отдельная ручная проверка п.5, не тест.

## README

`README.md` на русском в корне демо-папки, короткое, разделы:
- Что это: ежедневный дайджест трендов GitHub по теме multi-agent, две категории по 12 репозиториев.
- Как открыть приложение: двойной клик `app/index.html` (по `file://`, без сервера); приложение стартует само при загрузке страницы.
- Как ввести токен: masked-поле на странице; где взять значение — в PowerShell выполнить `$env:GITHUB_TOKEN` и скопировать вывод; пояснение компромисса (env недоступен браузеру), гарантии: токен только в памяти, не в коде, не логируется, не в localStorage.
- Как запустить сбор state: `node app/collect.mjs` (нужен `GITHUB_TOKEN` в окружении), результат — `out/state.json`.
- Как запустить тесты: `node --test app/test`.
- Описание `out/state.json`: поля `generated_at`, `since`, `queries`, `fresh[]`, `updated[]` (по 12 записей, ключевые поля репозитория).
