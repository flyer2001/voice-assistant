# Дайджест трендов GitHub — тема «multi-agent»

## Назначение

Ежедневный дайджест трендов GitHub-репозиториев по теме **multi-agent**. Две категории
по 12 репозиториев, обе ранжированы по убыванию звёзд:

- **Свежие** — созданные за последние 7 дней (`created:>=<today−7>`);
- **Изменения** — с push за последние 7 дней (`pushed:>=<today−7>`).

Карточки идут по три в ряд (центрированная сетка ограниченной ширины), в карточках
выводится аватар владельца репозитория (`owner.avatar_url`); клик по карточке раскрывает
подробную информацию прямо внутри карточки. Две темы: светлая (по умолчанию) и тёмная.
Есть индикатор прогресса загрузки. Источник данных — только GitHub REST Search API
(два запроса на прогон).

## Требования

- Node.js 20+ (для `collect.mjs` и тестов; проверено на Node v24.14.1).
- Переменная среды `GITHUB_TOKEN` — персональный токен GitHub (для `node app/collect.mjs`;
  браузер получает её через генерируемый `app/session.js`, либо вводит в masked-поле).
- npm-зависимостей нет — только vanilla JS и встроенные модули Node.

## Запуск приложения (без сервера)

**Автозапуск с env-токеном** (рекомендуемый путь): один раз выполнить
`node app/collect.mjs` при заданной `GITHUB_TOKEN` — он, помимо `out/state.json`,
генерирует `app/session.js` с токеном текущей сессии. После этого двойной клик по
`app/index.html` (открытие по `file://`): при загрузке страницы приложение само
подхватит токен из сессии и запустит сбор дайджеста без действий пользователя.
Сессия считается свежей 24 часа с момента генерации (`generated_at`); после
истечения — перегенерируйте её повторным `node app/collect.mjs`.

**Запасной путь**: если `app/session.js` отсутствует или сессия устарела, на странице
показывается подсказка и токен можно ввести в masked-поле (`$env:GITHUB_TOKEN` в
PowerShell, скопировать вывод) — сбор начнётся сразу после ввода. Переменные среды
браузеру напрямую недоступны — это ограничение среды (зафиксировано в research).

Гарантии: токен не вшит в код приложения (`index.html`, `lib/*.mjs`), не логируется,
не попадает в localStorage/sessionStorage/URL/cookie; в памяти страницы он только после
подхвата из сессии или ввода.

> **Внимание: `app/session.js` содержит секрет** (значение токена). Это генерируемый
> артефакт данных, а не код приложения — не коммитьте его в git, при необходимости
> удалите (`Remove-Item app/session.js`). Срок свежести — 24 часа.

## Сбор state-файла

```powershell
$env:GITHUB_TOKEN = "<токен>"   # если ещё не задана
node app/collect.mjs            # код возврата 0 при успехе
```

Без `GITHUB_TOKEN` скрипт сразу завершается с кодом 1 и подсказкой, сетевых запросов не делает.

## Тесты

```powershell
node --test "app/test/*.test.js"   # все тесты зелёные: 21 pass / 0 fail
node --test                        # вариант из корня демо-папки (тоже работает)
```

Примечание: в Node v24 форма `node --test app/test` трактует аргумент как файл и падает
(`MODULE_NOT_FOUND`) — используйте команды выше. Тесты не обращаются к сети (fetch подменён)
и не читают секреты (реальный `GITHUB_TOKEN` в дочерние процессы не передаётся).

## Расположение результатов

- `out/state.json` — результат сбора: `generated_at`, `since` (граница 7 дней), `queries`
  (тексты запросов), `fresh[]` и `updated[]` — по 12 записей с полями `full_name`,
  `html_url`, `description`, `stargazers_count`, `forks_count`, `open_issues_count`,
  `language`, `created_at`, `updated_at`, `pushed_at`, `owner_login`, `owner_avatar_url`,
  `topics`, `license_spdx_id`.
- `app/index.html` — одностраничное приложение (инлайновый скрипт; единственный внешний
  скрипт — генерируемый `session.js`, его отсутствие не ломает страницу).
- `app/lib/*.mjs` — модули (date, query, queue, sort, render, state, session);
  `app/collect.mjs` — точка входа Node; `app/test/` — тесты и фикстуры.
- `app/session.js` — **генерируемый** файл текущей сессии (`window.__GH_SESSION =
  {"token": ..., "generated_at": ...}`); содержит секрет, не коммитить, срок свежести 24 ч.
