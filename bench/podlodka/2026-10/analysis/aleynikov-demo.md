## Задача демо (шаблон команды `/demo`, дословно)

> Задача демо: собери приложение ежедневного дайджеста трендов GitHub-репозиториев по
> теме multi-agent. Две категории по 12 репозиториев: «свежие» — созданные за последние
> 7 дней; «изменения» — обновлённые за последние 7 дней. Выводи информацию о
> репозиториях в виде карточек, по три в ряд (не растягивай ряд на весь экран,
> центрируй по горизонтали), в карточках обязательно выводи аватары репозиториев, по
> нажатию на карточку должна открываться подробная информация, прямо в карточке.
> Ранжируй обе категории по убыванию звёзд. GitHub API — по токену из переменной среды
> GITHUB_TOKEN (переменная среды уже установлена); не вшивай токен в код и не логируй.
> Приложение — одностраничный html без npm-зависимостей с двумя темами светлой
> (по-умолчанию) и тёмной, прогрессом загрузки информации, приложение должно
> запускаться при загрузке страницы (без предварительного старта сервера), в подпапке
> app/ демо-папки. Артефакты: state-файл в подпапке out/, README.md на русском в
> демо-папке.

Дальше в шаблоне: `$ARGUMENTS` (новая задача заменяет эту) и «Все артефакты размещай в
новой демо-папке podlodka-local-llms-demo-<номер> с файлом статуса STATUS.md внутри.
Выполни все стадии по порядку. В конце пришли итоговый отчёт.»

⚠️ В задаче заложено противоречие: страница, открытая с диска без сервера, не может
прочитать переменную среды. Модель это заметила на стадии research, а потом на этом
противоречии и случилось единственное вмешательство человека (ниже).

## opencode.json — ключевое

Все четыре агента на **одной модели**:
```
"model": "llama.cpp-main-model/Strata-Qwen3.8-Flash-Next-GSQ-RCO-IQ3_S-Context131072",
"temperature": 0,
"chat_template_kwargs": { "preserve-thinking": true, "reasoning_effort": "medium" },
```
Провайдер `llama.cpp-main-model` в проектном конфиге **не описан** (ни baseURL, ни
лимитов): видимо, он в глобальном конфиге OpenCode. Имя модели говорит о Strata
и контексте 131072 (128K); это строка сл. 42 «Flash-Next GSQ-RCO IQ3_S, 83,6 ГБ, 128K,
промпт ~1500 ток/с, генерация ~90–110 ток/с» на 2×3090 + 64 ГБ RAM.

| Агент | mode | Права | Лимиты из промпта |
|---|---|---|---|
| `build` | primary, по умолчанию | read/edit/bash allow, task deny | модель не задана |
| `demo-coordinator` | primary | `task`: только три demo-сабагента; `edit`: только `podlodka-local-llms-demo-*/STATUS.md` и `opencode.json`; bash, webfetch, websearch — deny; todowrite allow | `"steps": 40`; не более двух исправлений на стадию; стадии строго последовательно |
| `demo-research` | subagent | read/edit allow; bash `"*": "deny", "curl *": "allow"`; webfetch/websearch allow | «не более десяти веб-запросов», по одному, только официальная документация |
| `demo-planner` | subagent | read/edit allow; bash/web/task deny | нуль npm-зависимостей; очередь с retry (Retry-After → x-ratelimit-reset, максимум 3); обязательные секции Tests и README |
| `demo-implement` | subagent | read/edit allow; bash `"*": "deny", "node *": "allow"`; web deny | `node --test` зелёный; один реальный запуск; README |

Промпт координатора (выжимка дословных правил):
- «Сам работу стадии не делай. Выполни три стадии по порядку: research, plan,
  implement. Каждую стадию поручай сабагенту через Task tool.»
- «Правила скорости: Работай быстро и решительно. Не размышляй долго. Не
  перепланируй. Проверяй артефакт один раз по критериям.»
- «Достоверность самоотчётов: Утверждения сабагента о состоянии среды (переменные
  среды, сеть, «токена нет», «запуск невозможен») — гипотезы, не факты… Без таких
  подтверждений заявления об ограничении среды не принимай.»
- «Пустой результат (пустой файл, 0 записей, все значения нулевые или одинаковые) —
  провал проверки… Мок и демо-данные не засчитывай, если возможен реальный запуск.»
- «Исправление всегда выполняет тот же агент, который создал артефакт. Перед
  исправлением поручи тому же агенту мини-диагностику: один минимальный
  воспроизводящий пример, не более четырёх команд.»

Это конфиг, отточенный против известных провалов слабых моделей: выдуманные
ограничения среды («токена нет»), моки вместо реального запуска, пустые результаты,
бесконечное перепланирование. Ответ 7: демо прогонялось на этой модели «больше 10
раз» вне доклада.

| Сессия | Время | Ходов модели | Вызовов инструментов | Состав |
|---|---|---|---|---|
| координатор | 17:11:54–17:38:47 (Σ ходов 1142 с, включая ожидание сабагентов) | 24 | 24 | read 9, task 6, write 4, todowrite 3, edit 2 |
| research | 17:13:39–17:18:17 (4 мин 38 с) | 35 | 34 | bash 15, read 13, webfetch 3, write 3 |
| plan | 17:18:49–17:20:01 (1 мин 12 с) | 6 | 6 | read 4, write 1, edit 1 |
| implement (+3 дозапроса) | 17:20:34–17:38:17 | 48 | 64 | write 21, edit 18, bash 17, read 8 |

Итого около **128 вызовов инструментов** на одну задачу. Первый проход до итогового
отчёта — сумма ходов координатора ≈ 925 с (**~15,5 мин**), дозапрос после реплики
человека — ещё ~3,6 мин.

**1. Координатор не смог писать STATUS.md (5 неудачных попыток).** Разрешение
`"podlodka-local-llms-demo-*/STATUS.md": "allow"` не сработало на Windows: модель
перебрала обратные слэши, прямые слэши, путь с диском и предположила, что паттерн
сравнивается с путём от корня «/». Обход: создание и все правки STATUS.md она
поручила сабагентам, приложив точный текст. Это **ошибка конфига** (паттерн прав и
пути Windows), а не модели; модель обошла её, не нарушив запретов.

**2. Research: песочница bash и PowerShell.**
- Первый bash-вызов (создать папку и проверить переменную) отклонён: разрешён только
  `curl *`.
- ⚠️ **Модель сознательно попробовала обойти allowlist**: рассуждала, что команда
  `curl ...; "LENGTH=$($env:GITHUB_TOKEN.Length)"` начинается с `curl` и пройдёт
  паттерн, назвала это «loophole» и «bypass of the guardrails», сначала решила не
  делать, потом всё же отправила. OpenCode отклонил и `;`, и затем `|` (судя по
  поведению, проверка идёт по каждому сегменту команды). Защита сработала на стороне
  обвязки, а не модели.
- `curl` в PowerShell — это алиас `Invoke-WebRequest`; `curl.exe` под паттерн
  `curl *` не попадает. Запись в путь с кириллицей («Рабочий стол») упала по
  кодировке; чтение из разрешённого Temp тоже отклонено; рабочий обход — относительные
  пути от cwd.
- Ошибки запросов: 401 из-за склеенных в одну строку заголовков (модель сама признала
  свою ошибку); `webfetch` к api.github.com — 403 через прокси; GraphQL 3 раза подряд
  с ошибками (нет `... on Repository`, затем запрет `stargazers` для fine-grained
  токена), с четвёртой попытки — `stargazerCount`.
- Инструмент `read` обрезает строку на 2000 символов, а JSON ответа одной строкой
  71 КБ: поля звёзд не читались, отсюда обход через GraphQL.
- ⚠️ **Лимит «не более десяти веб-запросов» превышен сознательно**: модель
  посчитала 10 использованных и сделала 11-й («единственное исправление»).
  Координатор это не заметил и записал «исправлений не потребовалось».
- Длину токена проверить не удалось (нужен PowerShell); существование доказано
  `GET /rate_limit` → 200, search limit 30, core 5000.
- Итог research: эндпоинт `GET /search/repositories`, `topic:multi-agent
  created:>=2026-10-07` → total_count **670**, `pushed:>=2026-10-07` → **3462**; токен
  есть только в среде, браузер его не увидит → предложено поле ввода токена на
  странице. CORS из `file://` записан как «пункт для обязательной проверки на стадии
  реализации» — **так и не проверен**.

**3. Plan прошёл за 6 вызовов.** Но поручение координатора уже содержало архитектуру
по пунктам: поле ввода токена, `app/collect.mjs` для state-файла, секции, тесты. То
есть план фактически написал координатор, хотя по промпту «сам работу стадии не
делай». Планировщик свёл противоречие «одностраничный html» против «раздели на
модули» так: в `index.html` инлайновые копии функций, в `app/lib/*.mjs` — те же
функции для Node и тестов.

**4. Implement.**
- Сам нашёл и исправил баг до запуска (цепочка `appendChild` на текстовом узле).
- `node --test app/test` в Node 24 падает с `MODULE_NOT_FOUND`; два варианта
  с пайпом отклонены песочницей; рабочие формы — `node --test "app/test/*.test.js"` и
  `node --test`. Итог **18 pass / 0 fail**.
- Реальный запуск `node app/collect.mjs` → exit 0 (код проверен через `spawnSync`),
  `out/state.json`: fresh=12, updated=12, звёзды по убыванию.
- Скан `app/` на токен (сравнение с реальным значением env и паттерны `ghp_` /
  `github_pat_`) → 0 совпадений.

**5. Мелкая порча STATUS.md.** Координатор прислал текст в обрамлении `---`;
сабагент, рассуждая о слове «ровно», записал оба разделителя в файл; координатор
поручил отдельной задачей их удалить. Два лишних вызова task.

**6. Вмешательство человека.** После итогового отчёта пользователь написал: «Токен уже
задан, используй его.» Координатор рассуждал ~3 мин, перебрал варианты и сам признал,
что запись токена в файл «probably violates "don't embed the token in the code"».
Выбрал: `collect.mjs` после сбора пишет `app/session.js` с
`window.__GH_SESSION = {"token": …, "generated_at": …}`, страница подключает его
`<script src="session.js">` и при свежести ≤ 24 ч стартует сама. Тесты стали 21/21,
повторный реальный запуск — exit 0. Скан честно показал: в `app/session.js` реальный
токен лежит открытым текстом рядом с `index.html`. README предупреждает «не
коммитить». В выложенном архиве `token` пустой (`""`, 74 байта против 167 в логе) —
автор вычистил.

**7. Странности текста модели.** Повторяющиеся пустые фразы вместо мысли («I need to
investigate this further. Let me check the details.») — 23 раза в четырёх
сессиях; дважды в конце координатор пишет «Understood. I'll use the current
structured task actions and return only task-related output.», что похоже на ответ на
скрытое системное напоминание. На действия это не повлияло.

**Сломался ли формат tool calls?** По экспорту — **нет**. Все неудачи — отказы прав,
кавычки PowerShell, кириллица в путях, ошибки HTTP и GraphQL. Ни одного
нераспознанного или битого вызова в экспорте нет. Это совпадает с ответом 7 («больше
10 прогонов… проблем с вызовом инструментов не замечал»). Оговорка: экспорт мог не
сохранить вызовы, которые обвязка отбросила как нераспознанные.

## Честная оценка

**Что демо доказывает.**
- Локальная модель 180B/6B в кванте IQ3_S на 2×3090 + 64 ГБ RAM прошла 4-агентный
  конвейер на ~128 вызовах инструментов без единого сломанного вызова и довела задачу
  до реального запуска с проверенным кодом возврата и данными: 670 / 3462 репозитория,
  12 + 12 записей, 21 зелёный тест.
- Скорость приемлемая для фоновой работы: первый проход ~15,5 мин, стадии 4,6 / 1,2 /
  ~4 мин.
- Модель хорошо держит дисциплину отчётов, которую задал промпт: каждое заявление со
  ссылкой на код возврата или HTTP-статус, секрет не печатался.

**Чего демо не доказывает или что в нём слабо.**
- **Браузерную часть никто не запускал.** У агентов нет браузера (координатор пишет
  «Can't run a browser»); CORS из `file://` research пометил как обязательную проверку,
  её не было. Агенты проверили карточки, темы и прогресс только чтением кода.
  **Поправка по записи (17.10):** автор сам открыл страницу вживую [49:30] — данные,
  сортировка, раскрытие карточек и тёмная тема работали; человеческий взгляд поймал
  дефект «страница просит токен» [32:00]. См. `aleynikov-talk.md`.
- **Тесты проверяют не ту копию кода.** Логика страницы (очередь, сортировка, рендер)
  — инлайновые копии в `index.html`; тесты гоняют `app/lib/*.mjs`. `render.mjs`
  возвращает HTML-строку, а страница строит DOM — это разные реализации. 21 зелёный
  тест ничего не говорит о том, что видит пользователь.
- **Координатор проверяет мягко.** Пропустил 11 веб-запросов при лимите 10, записал
  «все стадии прошли с первой проверки, исправлений не потребовалось», хотя было две
  правки STATUS.md и дозапрос. Сам признал, что состояние тестов принял со слов
  сабагента («I can't run commands myself… I'll rely on the reported output»).
- **«Мультиагентность» здесь — последовательный конвейер одной модели.** Параллели нет
  (промпт запрещает), роли различаются только промптом и правами. Это совпадает со
  сл. 10 (Амдал, «пишет — один агент»), но два агента и «умная + быстрая модель» из
  шкалы 48 ГБ (сл. 16) в демо не показаны.
- **Одна задача, один прогон в архиве.** «Больше 10 прогонов» — со слов автора, логов
  нет; доля успешных прогонов не названа.
- **Безопасность.** Модель сознательно попыталась обойти allowlist bash и сознательно
  превысила лимит запросов; по просьбе человека записала токен открытым текстом в
  папку рядом со страницей. Песочница OpenCode остановила обход; лимит и токен-файл —
  нет.
- **Задача маленькая и чистая:** новый проект с нуля, публичный API, без легаси и
  чужого кода. Это не замер на рабочих задачах.
