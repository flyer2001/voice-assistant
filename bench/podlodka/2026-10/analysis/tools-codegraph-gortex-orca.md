## 1. codegraph (colbymchenry)

**Что это технически.** Локальный граф символов и вызовов в SQLite
(`.codegraph/codegraph.db`, FTS5). Парсинг: нативное Rust-ядро на tree-sitter,
заявлено 20+ языков с «портативным» запасным движком для остальных. Агенту отдаёт
MCP-сервером (`codegraph serve --mcp`) с одним основным тулом `codegraph_explore`,
есть CLI и установщик под Claude Code, Cursor, Codex и другие. File watcher с
debounce обновляет индекс. LSP не используется. [П]

**Факты.** 73 797 звёзд, создан 2026-01-18, последний push 2026-10-12, MIT,
1 423 коммита, 554 открытых issue. [П, GitHub API]
Звёзды очень высокие для 9 месяцев. Накрутку не проверял, но число не
доказывает качество.

**Замеры (самоотчёт README).** [П] В среднем −62% токенов, −44% стоимости, −88%
вызовов инструментов. Для Alamofire (Swift): −59% токенов, 4 вызова против 33,
54 с против 2м22с. [Pplx подтверждает цифры по Alamofire.]
Методика: `claude -p` на Opus, один вопрос про архитектуру на репо, медиана из 4
прогонов, **в контрольной ветке CLI codegraph заблокирован**, 7 репо. Сам README
признаёт, что к концу сессии в контексте остаётся на ~80% больше retrieval-данных
(VS Code: 67k против 18k).
Независимых замеров не найдено [Pplx]. Замеров качества ответа или успеха
правки нет. Измерены только токены на вопросы «объясни архитектуру».

**Swift: ДА.** В таблице языков «Full support» для `.swift`, в бенчмарке есть
Alamofire. [П] Что именно стоит за «Full» (только tree-sitter-swift, без
SourceKit/IndexStore), README не раскрывает. Из этого следует, что разрешение
протоколов, extension, макросов и условной компиляции будет синтаксическим, а не
компиляторным. Это ровно потолок «~50% связей» из слов Родиона. Для Swift
цена отсутствия типизации: протокольные witness'ы, DI, генерация (SwiftGen,
Sourcery, макросы) и `#if` не разрешатся. Добавлять ничего не надо, грамматика уже
есть. Вопрос только в точности.

**Лучше и хуже того, что есть.** Лучше голого grep на вопросах «как устроено» и
«кто вызывает»: меньше шагов, это правдоподобно. Хуже: индекс может отставать при
правках агента, ветках и worktree (`.codegraph` лежит в репо, на каждый worktree
свой). Нет оценки precision/recall против компилятора. Нет честного базового
варианта «grep + Read без блокировки».

**Вердикт: дополнить HYP-041, гипотезу не заводить.** HYP-041 уже в статусе
DEFERRED и ссылается на ast-index, aider repomap, code-index-mcp, то есть класс
тот же. Добавить codegraph как кандидата №1 (есть Swift, MIT, MCP, локально) и
заменить ему критерий приёмки на замер из раздела «Эксперимент». Снять DEFERRED
имеет смысл только после замера.

## 2. gortex (zzet)

**Что это технически.** Один статический Go-бинарь: граф кода в SQLite,
tree-sitter (заявлено 257 грамматик) плюс «in-process resolvers» плюс опциональный
LSP для «compiler-grade» разрешения на избранных языках. CLI, MCP (stdio и HTTP),
REST `/v1/*`, веб-UI. Multi-repo в одном графе с межрепозиторными рёбрами,
fsnotify-watcher, демон. [П]

**Факты.** 1 894 звезды, создан 2026-04-06, последний push 2026-10-11,
Apache-2.0, 4 796 коммитов (при возрасте 6 месяцев, это ~25 в день, то есть, судя
по всему, активно пишется агентами), 86 открытых issue, один автор (Andrey
Kumanyaev). [П] README сам себе противоречит: 175 MCP-тулов против «100+», 19
агентов против 20. [П]

**Замеры.** «До 50× меньше токенов на ответ», «93,3% экономии» на дашборде
(11,2 млн токенов, $168,69). Базовая линия: «наивное чтение файлов целиком». [П]
Это не сравнение с grep-агентом. BENCHMARK.md и BENCHMARK-SWE.md не открывал.
Независимых оценок нет [Pplx], статьи про сравнение лежат на собственном сайте
автора.

**Swift: ДА по README, качество не проверено.** README причисляет Swift к языкам
с LSP-разрешением (предположительно SourceKit-LSP, это надо подтвердить в
docs/lsp.md, я не открывал). [П] Если это верно, gortex единственный из двух,
кто может подобраться к компиляторной точности на Swift. Но LSP-разрешение
требует собранного проекта, рабочего sourcekit-lsp и build-контекста (SwiftPM,
Xcode). Для Xcode-проекта без `buildServer.json` это отдельная боль. [GPT]
Цена добавления языка не стоит, он уже есть.

**Лучше и хуже.** Лучше: LSP-слой (потенциально), multi-repo под парк репозиториев
Sergey'я, daemon. Хуже: 175 тулов это тяжёлые описания схем в каждом запросе и
шанс, что агент путается в выборе. Есть режим отбора тулов, но это та самая
настройка, о которой коллега спросил «нужно ли». Один автор, быстрый темп
коммитов, высокий риск поломок и дрейфа API. Дублирует часть inbox/dispatch?
Нет, это не надзор.

**Вердикт: не брать как отдельную гипотезу, использовать как вторую ветку в том
же эксперименте HYP-041.** Если codegraph проиграет на Swift из-за отсутствия
типизации, gortex с LSP остаётся единственным оправданием индексатора вообще. Если
codegraph выиграет, gortex не нужен (избыточен, много настройки).

## 3. orca (stablyai)

**Что это технически.** Десктопное приложение (Electron + Vite + TypeScript, это
вывод по `electron.vite.config.ts`, README стек не называет). Запускает много CLI-
агентов (заявлено ~35, включая Claude Code, Codex, Devin) каждого в своём git
worktree, терминалы, встроенный браузер, интеграция с GitHub и Linear, SSH-
worktree с автопереподключением и пробросом портов, уведомления «агент закончил
или ждёт», usage-трекер лимитов Claude/Codex, мобильный компаньон через релей в
`cloud/`. [П]

**Факты.** 90 228 звёзд, создан 2026-03-17, последний push 2026-10-12, MIT,
13 756 коммитов, **8 195 открытых issue**. [П, GitHub API] Поддержка Swift не
применима (не индексатор). Телеметрия анонимная, отключаемая; мобильный пейринг
идёт через облачный релей. [П]

**Чем отличается от нескольких терминалов и ssh.** Реально новое: единая панель
«кто ждёт меня», worktree на агента из коробки, уведомление, мобильный follow-up,
сравнение результатов одного промпта на нескольких агентах. Всё остальное
(запуск на удалённой машине, надзор, heartbeat, эскалация) у Sergey'я уже есть:
`hb`, dispatch на воркеров, inbox. Эскалации по таймауту, жёсткого heartbeat и
файловой памяти у Orca не заявлено. [П, по README]

**Лучше и хуже.** Лучше: визуальный «дашборд внимания» для HYP-047 (обход по
таймеру, 4-5 сессий). Хуже: это GUI на десктопе, а агенты Sergey'я живут на VDS
по ssh и ходят через Happy и tmux, то есть Orca встаёт ещё одним слоем состояния
рядом с sessions-db и inbox. Лишний источник правды. Релей через чужое облако.
8 195 открытых issue говорят, что поддержка не успевает за ростом. [GPT]: типичная
смерть таких обёрток в том, что работа живёт в CLI, CI и ssh, а не в окне.

**Вердикт: не брать.** Дублирует надзор. Единственная ценная идея, «доска
ожидающих внимания», проверяется без Orca: в HYP-047 уже обход по таймеру. Если
понадобится, добавить в HYP-047 строку «Orca как референс интерфейса, не как
зависимость». Гипотезу не заводить.

## Скептик (gpt-5) и что из этого принято

[GPT], аргументы, проверенные на соответствие фактам выше:
- Контрольная ветка codegraph с заблокированным CLI занижает базу. Принято:
  факт README, в контроле у агента не было codegraph, но был grep, так что
  претензия смягчена, всё равно N=1 вопрос на репо.
- Токены не равны успеху. Принято, в обоих README нет метрики корректности.
- 175 тулов gortex: стоимость схем не засчитана. Принято, это
  вероятный скрытый минус, но замера нет.
- «Claude Code отказался от векторного индекса в пользу агентского grep». Это
  утверждение скептика, мной не проверялось, брать как контекст, не как факт.
- Swift: макросы, кодоген, `#if`, DI, протокольные witness'ы, SwiftPM-таргеты и
  генерируемый код в DerivedData ломают синтаксический индекс. Принято как риск,
  точность для Swift нигде не измерена. Совпадает с «50% связей» Родиона и с
  выводом HYP-041 про «Swift AST без SourceKit».
- Устаревание индекса при правках агента и worktree. Принято, это пункты 7-9
  в `questions-rodion.md`, ответа Родиона не было (идти в бар 16.10).
- Не принято без проверки: «деньги на токенах не окупают инструмент». Данных
  нет в обе стороны.

## Что протестировать первым: эксперимент на час

Гипотеза к проверке (HYP-041): индекс сокращает токены на Swift-задаче **без
потери точности ответа** против `rg` + Read. Один Swift-репозиторий Sergey'я
(например `telegram-client` или `voice-assistant`), на mac-home.

1. (10 мин) Поставить codegraph, `codegraph init` в репо. Gortex второй веткой,
   только если время остаётся.
2. (35 мин) 5 задач, которые уже решались руками и ответ известен: найти
   реализацию протокола по вызову; все вызовы функции через несколько
   SPM-таргетов; что синтезирует макрос или кодоген; различие веток `#if`;
   список файлов для безопасного переименования. Три прогона на задачу:
   (a) голый Claude Code, (b) с codegraph, (c) с codegraph, но после ручного
   переноса файла без переиндексации. Тот же промпт, свежая сессия, одна модель.
3. (10 мин) Считать: токены (по логам сессии, включая схему MCP), число вызовов,
   время, и главное **верно/неверно** по заранее записанному эталону
   (вердикт руками, по git diff реального решения).
4. (5 мин) Критерий провала: экономия токенов менее 30%, или неверных ответов
   больше, чем в (a) хотя бы на 2 задачах из 5, или в (c) индекс отдал устаревший
   путь без предупреждения. Тогда HYP-041 остаётся DEFERRED, с записью
   «индекс не окупается на Swift без IndexStore».

Порядок вне этого часа: если codegraph провалился на типизации, второй
эксперимент это gortex с sourcekit-lsp, и только потом вопрос про «golden от
компилятора» из доклада Родиона.
