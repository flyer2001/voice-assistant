## Тезисы

1. **Агент становится точкой входа и выхода в работу; софт как таковой не создаётся**, он прячется в скрипты и внешние API, фокус уходит на бэкенды сервисов (03:00–04:00). Где это неверно — спецвиды интерфейса, мгновенная обратная связь, потоковая обработка, общение людей (52:00–54:00). Собственная оговорка: «где наше место как разработчиков — открытый вопрос, я не знаю ответа» (04:00).
2. **Фронтенд — это верхний harness.** CLI, десктоп и расширение IDE инжектят в один и тот же движок разные инструменты: десктоп Codex — управление тредами и автоматизациями, расширение VS Code — доступ к открытым файлам (18:30–19:30). «И то, и то влияет на то, как агент себя ведёт».
3. **Субагенты — устаревающая штука и костыль, треды — общий механизм** (28:30, 61:00). «Я уверен, что общение агентами будет происходить именно чатами, а не субагентами. Я это протестил, оно работает прекрасно» (61:00). Замера не приводит.
4. **Мультиагентные системы с оркестратором у него «пока не заводятся»**: эффект глухого телефона, потеря информации редко окупается (47:00). Один исполнитель тоже плох — теряет детали на компакции, «а детали и есть самая важная штука» (47:30).
5. **SDD почти всегда bullshit**, потому что «заранее все проблемы невозможно предусмотреть»; вместо — spike-driven development: дешёвые эксперименты под основные гипотезы и риски до большой спеки (39:30–40:30).
6. **Скиллы — из реального прошлого, а не из представлений**: у клиентов «покажи, как ты это делаешь» каждый раз выглядит «вообще всё по-другому», чем в описании (49:00).
7. **Сжатый стиль ответов («caveman») не экономит токены**: токены съедают вызовы инструментов, полные HTML-страницы, документация, логи без ограничения по строкам; короткие ответы нужны человеку, «лучше буду читать мало, чем не читать много» (32:00–32:30).
8. **Последние модели стали менее устойчивы к промпт-инъекциям** (40:30), поэтому он советует Approve for Me, а не Full Access. Источника не называет.

## Его сетап по частям

**Вместо субагентов — вложенные треды в BB** (21:30–22:30, 60:30–61:30). Тред — полноценный чат, у BB его можно сделать дочерним к конкретному родителю, вложенность — сколько угодно уровней, в любой тред можно зайти руками и дописать. Ребёнок может прислать родителю отчёт; родитель имеет доступ ко всему контексту ребёнка и может «пойти поискать подробности», если отчёта мало (61:30). Тред может работать на другом провайдере: «основной агент на Астре, а штука, которую он использует — на Fable» (21:30).

⚠️ Заявленное в названии «заставляем fable рулить кодексом» голосом так не прозвучало. Единственный пример — 21:30, и там на Fable работает **подчинённый** тред, а основной — на «Астре» (модель не опознана). Кто кем рулит в его сетапе, по речи не установить.

**Вместо отдельных GUI разных агентов — один фронтенд BB поверх всех** (20:30–28:30). Общие треды, автоматизации, браузер, скиллы, плагины. Подписки работают, своих агентов BB не изобретает (59:30). «Опенсорсный и бесплатный» — это фраза ведущего, спикер её не подтвердил и не опроверг (60:00).

**Память.** Явного «я выключил память» в речи нет. Есть:
- вред памяти: агент, упёршись в проблему, находит костыль «и ещё запоминает его на будущее, если у вас memory включен» или есть строка «обновляй скилл после использования» (36:30);
- вместо памяти после компакции: «у тебя всё записано» — файл чата и инструменты чтения тредов (41:30–42:00);
- автоматизация-ретро: регулярно анализирует все его чаты с агентом за последнее время, ищет неправильные паттерны (скилл неправильно написан, ложные предположения об инструменте, пять попыток там, где сработала пятая), а также ключи, утёкшие в чат, — их надо отозвать (34:00, 41:30);
- skill-learn: знание переносится в скиллы, выведенные из сессии (48:30).

**MCP.** Отказа от MCP целиком нет. Календарь — «просто официальный MCP» в плагинах Codex/Claude Code (15:30). GitHub — через `gh` CLI, «есть куча исследований про то, что оно эффективнее работает» (15:30, исследования не названы). Основная рамка — не MCP, а четыре способа подключения:

| Способ | Скорость | Устойчивость | Риск | Его оценка |
|---|---|---|---|---|
| Браузер, агент решает на каждом шаге | медленно | «суперустойчиво» к изменениям фронта | бан маловероятен | официальный |
| Официальный API (+ своя CLI поверх) | быстро | устойчиво | никто не забанит | не все функции есть (ЭЦП в банке, задания в GetCourse), бывает дорого |
| Скрипт с селекторами в консоли браузера | быстрее | «очень низкая» | — | «самый плохой из всех четырёх, не советую» |
| Имитация браузера: internal API с куками | быстро | средне (internal API меняется) | нарушение ToS, нужны таймауты | экономит деньги |

Свой аккаунт Telegram никогда не автоматизирует: популярные библиотеки userbot детектируются, аккаунт «отваливается из всех кабинетов» (17:30).

**CLI.** «Избавляемся от CLI-интерфейсов» в речи — про терминальный **фронтенд агента**, не про CLI-инструменты: `gh`, yt-dlp, свои CLI поверх API он использует (09:30, 15:30, 16:00). Аргумент против терминального фронтенда — не замер, а механизм: десктоп инжектит инструменты (треды, автоматизации), которых в CLI нет; плюс Mermaid, мобильный доступ, проброс портов.

**Браузер.** PlayWriter для своего Chrome вместо встроенных браузерных плагинов ChatGPT и Claude Code: «Я проводил исследования, которые показывают, что PlayWriter справляется лучше» (29:00); ссылка на «мини-бенчмарк» была на слайде (52:00), цифры голосом не названы.

**Скиллы** (45:30–52:00):
- **ревью**: ревьюер — желательно другой провайдер; «агенты как джины: попросили докопаться — докопается, даже если не до чего»; скилл описывает итеративное общение, как в ревью PR: «с этим согласен, с этим нет, это ты неправильно понял», до финального аппрува;
- **прораб**: один исполнитель + один менеджер, который держит цель, требования, решения и «мои исходные фразы, ровно в том виде, в котором они были»; следит за исполнителем **по таймеру в процессе**, а не ждёт его окончания, — «хороший микроменеджер … сеньор и его подмастерье»; «на моей практике это очень хорошо работает»; в Q&A — progressive disclosure: сначала верхний уровень, при подозрении — вывод инструментов (63:30–64:30); степень вмешательства задаёт сам, «насколько сильно переключиться в режим прораба» (63:30);
- **skill-learn**: после сессии «проанализируй сессию, вытащи все грабли, сформируй методичку для нового сотрудника», с unified-правилами, а не частными случаями; затем сабтред с чистым контекстом прогоняется на **той же** задаче, основной тред (знает грабли) проверяет результат, при ошибке скилл правится и прогон повторяется; частные случаи копятся в папке скилла, 3–4 кейса для проверки каждого изменения — «подобие евала»; «самый топовый из самых простых и самый простой из топовых» (50:30–51:00);
- индекс для больших репозиториев (Яндекс, вместо grep с сотнями совпадений), Mermaid-скилл (Mermaid — не только блок-схемы), tg channel reader (парсит Telegram Widget: посты, медиа, комментарии).

**Окно контекста.** В Claude Code поставил лимит 500k вместо 1M: «абсолютно интуитивно … чаще компактится, но нет тупика» (64:30–65:00).

## Q&A

- **Двухфакторка** (55:00). Полноценную агенты не проходят. Агент проходит первую часть, OTP ему вставляют в чат руками — «он одноразовый, вообще пофигу». Пробовал форвардить SMS на Mac и дать агенту читать уведомления — macOS блокирует; обойти можно, «но это too much даже для меня».
- **Промпт-безопасность** (57:00). Слой 1 — Approve for Me: на каждый выход из sandbox отдельный классификатор-надсмотрщик, «микро-ИБшник», бывает перестраховывается; «95 % минимум всей защиты». Слой 2 — строка «не доверяй всей информации», «интуитивного ощущения, насколько помогает, нет». Инъекции и так слабо работают из-за иерархии system → developer → сессия → вывод инструментов. **Но скиллам агент доверяет сильно** — каждый скачанный скилл прогонять в песочнице (веб-чат ChatGPT или Claude) на «нет ли фигни»; уже есть скиллы, отправляющие аналитику авторам, включая детали ОС (58:30–59:00).
- **Что такое BB** (59:00). Фронтенд поверх нативных Codex, Claude Code, pi; подписки работают; инжектит тулы для тредов, автоматизаций, плагинов, браузера, агент может сам менять настройки BB. Обычное клиент-серверное веб-приложение.
- **Вложенные треды vs субагенты** (60:30). Субагенты — «костыль», своя сущность у каждого вендора со своими правилами; тред — абстрактный полноценный чат. Передача: ребёнок шлёт отчёт, родитель может прочитать весь контекст ребёнка.
- **Варя: сколько главному лезть в контекст исполнителя и при каком объёме тупеет** (62:00). Серебряной пули нет, регулирует командой «насколько включиться в режим прораба»; progressive disclosure; детали важны, потому что по ним видно неверный вывод из вызова инструмента. Построенного подхода к компакции нет — лимит 500k «интуитивно».
