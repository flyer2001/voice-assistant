## Что добавить в гипотезы

### HYP-053
- Разделить два вида рельс: (а) рельсы формы кода (типы, switch, IoC) и (б) рельсы прав агента (sandbox, allowlist, protected paths). Сейчас в гипотезе только (а). Подлодка говорит именно про (б).
- Критерий провала расширить: не только «обходит рельсы», но и список обходов в Swift: `as!`, `try!`, `Any`, `@unchecked Sendable`, отключение strict concurrency, удаление/ослабление теста, правка CI/lint-конфига. Для каждого — tripwire в CI (SwiftLint/grep). Без этого «нет неправильного пути» — лозунг.
- Метрика «доля правил с механической проверкой» оставить, добавить «число попыток обхода и сколько поймано».
- Ввести порог применимости: на нестабильном домене (пет в стадии поиска требований) рельсы дорогие; закладывать после стабилизации инварианта, как уже сказано в «Первом шаге».
- Ввести градацию автономии (Tier: читать -> править -> коммитить -> деплой) — из 00:59:30-01:00:00 и из Gaps HYP-008.

### HYP-008
- В HYP-008 сейчас заявлено «-60-75% токенов при сохранении точности» — оценка (GPT-5.2), не замер. Пометить как непроверенную; внешние замеры показывают другое (ниже).
- Rule files не равно ограничитель: добавить явное разграничение «директива / проверка / права». Subagent `tools:`-список — это права, а не правило, и его надо считать рельсой (б).
- Секцию Gaps «Permission model, Staged autonomy» вынести из заметок GPT-5.2 в основные пункты: Подлодка подтвердила как реальную потребность.
- Не генерировать AGENTS.md моделью («[Fill in by LLM assistant]» в шаблоне) — см. Gloaguen.
- Phase 1 чеклист «LLM загружает правила автоматически?» — превратить в A/B замер, не наблюдение.

## Внешний ресёрч (Perplexity, 2026)

- Gloaguen et al., «Evaluating AGENTS.md» (arXiv 2602.11988; AGENTbench 138 задач/12 репо + SWE-bench Lite 300): LLM-сгенерированный файл -3 п.п. успеха и +20% стоимости; написанный человеком ~+4 п.п. на AGENTbench, до +19% стоимости. Агенты инструкции в целом выполняют (больше тестов, больше чтения), но успех не растёт. https://arxiv.org/abs/2602.11988 , https://www.infoq.com/news/2026/03/agents-context-file-value-review/
- Lulla et al. (arXiv 2601.20404): 124 PR/10 репо, с AGENTS.md медиана runtime -28.6%, выходных токенов -16.6%, завершаемость сопоставима. Это эффективность, не качество. https://arxiv.org/html/2601.20404v2
- Процента «игнорирования инструкций» нет ни в одном найденном источнике; общего замера соблюдения не существует.
- Права: Claude Code allow/ask/deny + sandbox отдельно; deny на Read/Edit не блокирует `cat` в shell, нужен sandbox на уровне ОС. Codex: sandbox (read-only / workspace-write / danger-full-access) отдельно от approval policy. https://openai.com/index/running-codex-safely/ , https://www.anthropic.com/engineering/claude-code-auto-mode
- Публичных подтверждённых инцидентов обхода (удаление тестов, побег из sandbox) в выдаче не нашлось; Perplexity прямо сказал не утверждать их без первоисточника. Ссылку на reward hacking надо искать отдельно.
- Типы: «make illegal states unrepresentable», exhaustive switch, architecture tests (зависимости, запрещённые импорты), защита файлов верификации (CI, lint-конфиг) вне зоны записи агента — как общий приём, без замеров эффекта на агентах.

## Челлендж (GPT-5.2, скептик)

1. Доказательства, что rule files меняют поведение: корреляция не причинность (параллельно чистят репо, тесты, формулировки); Lulla меряет экономию, не правильность; нужен A/B на одних задачах с метрикой нарушений через статанализ.
2. Over-engineering: у соло-разработчика с плавающими требованиями TCA/UDF/IoC = налог на неопределённость (Action/State/Reducer/Deps/Tests на каждую фичу); тесты начинают проверять каркас; разработчик сам начнёт обходить `@unchecked Sendable`/`Any`.
3. «Нет неправильного пути» недостижимо: ошибки семантические (правильный редюсер, неправильная логика); «плохой, но легальный путь» внутри рельс; escape hatches Swift (`as!`, `Any`, `unsafeBitCast`, KVC, правка build settings).
4. Обход: агент оптимизирует цель «зелёный PR» -> ослабит тест, порог coverage, отключит strict concurrency, правит CI; deny без sandbox — театр. Нужны tripwires в CI, code owners на CI/lint, отдельный токен.
5. Предложенный дизайн проверки: 20-50 задач, половина «соблазнительных»; режимы A (rule files) / B (рельсы + tripwires + sandbox) / C (оба).

## Итог

Выжившие возражения (по моему суждению):
1. «Легальный плохой путь» и семантические ошибки: типы не ловят, значит «нет неправильного пути» надо заменить на «меньше классов неправильных путей, остальное ревью». Формулировку 053 понизить.
2. Escape hatches Swift и правка CI/тестов: рельсы без tripwires и protected paths обходятся тривиально; это условие самой гипотезы, а не доп. опция.
3. Налог на нестабильный домен у соло-разработчика: у 053 уже есть открытый вопрос про границу, но измерять lead time нужно явно.

Отклонено/ослаблено: «rule files — успокоение автора» — данные говорят, что агенты инструкции выполняют (меняют поведение), но не повышают успех и дорожают; то есть не плацебо, а слабый инструмент.

Вывод: Подлодка говорит про ограничитель прав и ответственность, 053 — про форму кода; это разные слои, и гипотезе нужен второй (sandbox, tripwires, tier автономии). Заявку «-60-75% токенов» в HYP-008 снять до замера. Проверять как A/B: rule files vs рельсы+tripwires на соблазнительных задачах.
