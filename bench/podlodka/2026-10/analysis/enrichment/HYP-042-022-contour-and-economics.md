**Угрозы (0:53:00-0:54:30).**

- «Статья… взяли квен 2,5 и заложили туда бэкдор, что если пользователь вводит определённую фразу, например Hello Darling, то агент запускает внутреннего вредоноса и сносит всё» (0:53:30). Источник статьи не назван.
- Вывод спикера: «пользоваться Frontier зарубежными может быть более выгодно, потому что им невыгодно тебя сливать публично» (0:54:30).

**Где позиции противоречат друг другу:**
1. A и B расходятся по главному: данные не должны уходить вовсе против риска приемлем. B при этом сам признаёт, что своё железо ему не по бюджету, то есть спор идёт про деньги, не про безопасность.
2. B считает маскирование достаточной защитой, C считает достаточной защитой договор. Каждый закрывает «свой» риск и не видит риск другого: договор не помогает от утечки на стороне поставщика, маскирование не помогает от выдачи секретов в коде.
3. Тезис «им невыгодно сливать» (0:54:30) соседствует с «национализацией» (0:51:30). Репутационный стимул поставщика не защищает от государства.
4. C предупреждает про «потерю места» за личную подписку, а B называет отказ от фронтира глупым. Это два разных вопроса: легальность канала (C) и ценность модели (B). Их смешивают.
5. Бэкдор в Qwen (0:53:30) аргумент против открытых весов, то есть против политики A. Но A в эфире на эту угрозу не отвечает.
6. «Токен вдвое дороже ночью» (0:04:30) описывает загрузку для облака с поштучной арендой, а сам рассказчик в 0:50:00 говорит о нехватке карт для больших моделей. Это два разных ограничения: простой и ёмкость.

## 2. Что добавить в гипотезы (раздельно)

### HYP-042 — Avito GenAI Compliance
Сейчас: правила Avito (§1-§8) описаны как «что нельзя и как настроить». Из Подлодки добавить:
1. **Секцию «Политики других компаний по трём типам»** (A/B/C выше). Политика Avito ближе всего к C+gateway: запрет ПДн/секретов/КИ во внешние LLM, «Help improve Claude» выключить, LLM-gateway с анонимизацией. Полезно сравнить её по трём осям: канал (корп/личный), данные (маскирование/запрет), контур (внешний/внутренний).
2. **Пункт про границу «маскирование vs запрет».** Avito в §2 разрешает во внутренние LLM «через gateway с анонимизацией», то есть сама опирается на маскирование, которое на Подлодке названо «до 100% давайте попробуем». Нужно зафиксировать допустимую остаточную долю промаха и метрику recall (см. челлендж, оценка ниже не подтверждена).
3. **Пункт про «no-training ≠ no-retention».** В §4 стоит «Help improve Claude: выключить», но нет строки о сроках хранения и ZDR. Добавить проверочный вопрос к ИБ: есть ли ZDR-соглашение, какое хранение у нашего плана.
4. **Вектор «агент с доступом к проду»** (0:53:00): в чеклисте харденинга (§9) нужна отдельная строка про права агента, не только про данные.
5. **Предупреждение о личной подписке** (0:51:00-0:52:00): зафиксировать как внешнее подтверждение правила §7 про безопасность аккаунтов. Но честно отметить, что в части HYP-059 мы сами работаем на личной подписке, и это именно тот риск, о котором предупреждает C.

### HYP-022 — Local LLM Routing
1. **Новый довод «почему гибрид, а не всё локально».** Подлодка дала реальный практикующий ответ B: большие модели в своё железо не помещаются по бюджету стойки. Это совпадает с ограничением из самой гипотезы (4096 токенов у Apple FM, 6-12 tok/s у Qwen 35B на M1 Pro) и укрепляет роутинг «чувствительное локально, сложное во фронтир».
2. **Критерий маршрутизации по типу данных, не по сложности.** Сейчас роутер делит «sensitive code → local, complex → Claude API». Из эфира: ПДн/карты/медицина это отдельный класс, и именно для него нужна локальная маскирующая модель или детерминированный фильтр. Добавить в роутер ветку «маскирование перед внешним вызовом».
3. **Угроза «открытые веса = риск бэкдора»** (0:53:30) в раздел «Ограничения»: локальная модель не бесплатна по безопасности. Практика: проверять происхождение весов, не запускать pickle, давать локальной модели минимум прав. Конкретный Qwen-бэкдор в эфире не подтверждён (см. ресёрч).
4. **Метрика «простой железа»** (0:04:30): в разделе про свою машину (ubuntu-home) считать утилизацию GPU, иначе экономика локального слоя считается неверно.

### HYP-059 — выгода на подписке (только экономика)
1. Подлодка подтверждает разворот из §Экономика: спикер говорит о «реальной экономической эффективности, финансах, а не единице токена» (0:04:00). Для подписки это значит пропускную способность, как у нас.
2. **Граница применимости.** Тезис «экономия токенов не конвертируется в деньги» верен только пока подписка фиксирована. Для корпоративного контура с арендой GPU экономика обратная: простой дороже токена. Добавить в §Экономика явную развилку «подписка / API / своя карта», у каждой своя метрика выгоды.
3. Подписка за 200-300 долларов (0:50:30) названа как «глупо не пользоваться». Это даёт нижний ориентир для сравнения со своим железом (раздел «Итог»).

## 3. Внешний ресёрч (Perplexity, 2026-10-12)

Важная оговорка: Perplexity по большинству запросов вернул «не подтверждено источниками», это сохранено ниже как есть.

**Гарантии «не обучаемся на данных»:**
- Anthropic: ZDR по Claude API и Claude Code Enterprise даётся только с одобрения Anthropic, по организации, не автоматически. Исключения: юридические требования и борьба со злоупотреблениями, результаты safety-классификатора могут храниться. https://privacy.claude.com/en/articles/8956058-i-have-a-zero-data-retention-agreement-with-anthropic-what-products-does-it-apply-to
- OpenAI: бизнес-данные по умолчанию не идут в обучение, у Enterprise удалённые чаты стираются обычно в пределах 30 дней, API без ZDR хранит логи мониторинга злоупотреблений 30 дней. Приказ суда о сохранении данных (NYT) действовал до 26.09.2025, затем OpenAI продолжала хранить ограниченный набор данных апрель-сентябрь 2025. Enterprise и ZDR API под приказ не попадали. https://openai.com/index/response-to-nyt-data-demands/
- Google: Workspace не обучается на данных клиента без разрешения, но сроки хранения отдельные, и источники Google противоречат друг другу (от «не хранятся после сессии» до «90 дней и бессрочно» по настройкам админа). Кэш по умолчанию 24 часа. https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/zero-data-retention
- Утверждение о смене политики потребительских планов Claude (обучение по opt-in и хранение 5 лет) источниками **не подтверждено**.
- Конкретные корпоративные политики запрета и gateway-ов: **ничего не найдено**, это пробел.

**Экономика self-hosted (Perplexity, цифры из обзоров, не котировки):**
- Аренда H100 от 2,69 до 12,29 долларов в час (специализированные облака 3,49-6,16), H200 3,59-5,40, B200 2,71-6,39. Покупка: H100 25-40 тыс. долларов за карту, сервер на 8 карт 250-320 тыс. Стойка Blackwell 2-3 млн долларов, 120-130 кВт.
- Расчёт при допущении 100 токенов/с на карту: 9,03 доллара за миллион выходных токенов при 100% загрузки, 45,15 при 20%.
- Цены API для сравнения: DeepSeek V4-Flash 0,14 вход / 0,28 выход, V4-Pro 0,435 / 0,87, Qwen3.8 Max 2 / 6 долларов за миллион. https://tech-insider.org/ie/chatgpt-vs-deepseek-vs-qwen-2026/

- Источники: https://www.cloudzero.com/blog/h100-gpu-cost/ , https://www.mercatus-ai.com/blog/gpu-rental-prices , https://intuitionlabs.ai/articles/data-center-gpu-prices

**Инциденты:**
- **Подтверждён (в части факта):** Samsung, апрель 2023, сотрудники отправили в ChatGPT исходный код полупроводникового производства и содержание внутренней встречи; Samsung ограничил использование. Оговорка: основано на корейских СМИ, Samsung подтвердил не всё. Это утечка по вине сотрудника, а не «вытащил код из модели». https://www.theregister.com/software/2023/04/06/samsung-reportedly-leaked-its-own-secrets-through-chatgpt/895536

Это закладка в цепочке поставки, не prompt injection от пользователя. https://aws.amazon.com/security/security-bulletins/AWS-2025-015/

Это по памяти правдоподобно, но здесь не проверено, поэтому в выводах не используется как факт.

## 4. Челлендж (GPT, роль скептика)

Ответ скептика приведён в сжатом виде с моей оценкой достоверности.

**Возражения, которые выдержали проверку:**
1. **TCO своего кластера занижен на порядок.** Расчёт скептика: 8xH100 за 300 тыс. на 3 года = 100 тыс./год, хостинг 36 тыс., двое инженеров по 250 тыс. = 500 тыс., прочее 50 тыс.; итого около 686 тыс. в год. Допущения скептика (две штатные единицы, 160 ток/с суммарно при 20%) условные, но вывод о доминировании зарплаты над железом разумен. Оговорка к скептику: «100 токенов/с на карту» это скорость одного потока. Пакетное обслуживание (vLLM и подобное) даёт на той же карте многократно больше суммарных токенов, поэтому цифры 45-136 долларов за миллион завышены как для Perplexity, так и для скептика. Порядок величины после батчинга не измерен, оценки здесь нет.
2. **«Не обучаемся» не равно «не храним».** Подтверждено фактами из ресёрча: ZDR по одобрению, 30 дней логов злоупотреблений, приказ NYT. Ключ: защита работает «только когда настроена и одобрена».
3. **Маскирование даёт ложное чувство безопасности.** Структурированные данные (номер карты) ловятся хорошо, свободный текст (имена, диагнозы, контекст) хуже, а перекрёстная идентификация по косвенным признакам остаётся. Цифры скептика (recall около 95% для регулярок, F1 70-85% для NER на шумном тексте) **без источника, ориентир, не факт**. Остаётся и аргумент, что маскирование не закрывает секреты в коде и логах.

**Возражения, которые не выдержали или ослаблены:**
- «Подписка 200-300 долларов дёшево относительно кластера»: сравнение несоразмерно, но оно честно показывает, что для малой команды подписка рациональна. То есть B прав в своих рамках.
- «Из инцидентов подтверждены только два»: верно, но это говорит не «угроза выдумана», а «основные подтверждённые провалы это ошибка человека и цепочка поставки, не бэкдор в весах».
- Скептик ссылается на устаревшие модели (GPT-4o, Claude 3) и общие рассуждения, не измерения 2026. Относиться как к рамке, не как к данным.

**Где панель права (не пересаливать):**
- Для малых команд и экспериментов фронтир за 200-300 долларов в месяц действительно разумнее своей карты.
- Корпоративный договор с ZDR реально снимает часть рисков, если получен и настроен.
- «Национализация моделей» остаётся спекуляцией, но аргумент о правовом доступе к бэкапам (приказ NYT как прецедент) имеет фактическую основу.

## 5. Итог

Обогащение:
1. HYP-042: три политики (A своё железо, B дать гранату и маскировать, C корп-план да / личная подписка нет), политика Avito ближе к C+gateway; добавить в чеклист строки про ZDR/сроки хранения и права агента на прод.
2. HYP-022: гибридный роутинг подкреплён бюджетным аргументом B; добавить ветку «маскирование перед внешним вызовом» и риск происхождения открытых весов.
3. HYP-059: развилка «подписка / API / своя карта» с разной метрикой выгоды; для подписки метрика остаётся пропускной способностью.
4. Противоречия панели: A и B спорят про деньги, не про безопасность; C и B закрывают разные риски; «им невыгодно сливать» против «национализации».

Выжившие возражения: (1) скрытые издержки своего кластера (персонал, простой), (2) «не обучаемся» не равно «не храним», (3) маскирование не закрывает секреты и свободный текст.

Не подтверждено и в выводы не идёт: бэкдор Qwen 2.5, счётчики вредоносных моделей, 5-летнее хранение в потребительском Claude, 10-30% утилизации, цены Max/Pro, первоисточники CVE Cursor/Copilot.

**Экономика своего железа против подписки.** Для одного разработчика на фиксированной подписке своя карта не окупается ни по деньгам, ни по качеству: потолок у железа Sergey'я это 6-12 токенов/с на 35B MoE на M1 Pro, модель слабее фронтира, а связывающее ограничение подписки (окно контекста и rate limits) железо не снимает. Локальный слой оправдан не экономией, а закрытием класса данных, который нельзя выпускать наружу, и там измерять надо долю таких запросов, а не цену токена. Порог, когда своё железо выигрывает у API, требует измерения при батчинге и реальной загрузке, и этой цифры у нас нет.
